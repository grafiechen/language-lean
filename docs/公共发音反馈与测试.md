# 公共发音反馈与处理

词条和例句的“播放发音”旁提供“报告发音问题”。它只对公开资源显示，个人读音仍在个人内容中修正和重新生成。提交反馈需要联网登录；离线学习和待上传答题不受影响。

用户在弹窗中选择“读音不正确”或“无法播放或音频异常”，填写不超过1000字的说明。页面记录实际遇到的音频版本，服务器再次核对当前公开发音，并保存词典版本和文本快照。没有填写发音、私人资源、过期文本和不属于该公共资源的音频版本不能提交。窗口下方展示本人对此资源的反馈及处理说明，不展示他人的反馈。

后台新增“发音反馈”列表，支持待处理、已修复、无需修复和全部状态筛选，每页20条。点击列表项打开处理窗口，展示问题快照及当前公开发音。需要修改发音文本时，点击“打开基础词典修正”，使用原词典编辑器保存草稿并发布；未发布草稿不会进入用户反馈或公开音频。

管理员点击“生成新的公共音频”，仍使用已有生成锁和版本追加机制。生成失败、未配置云服务或资源封禁时，反馈保持待处理。生成成功后试听并填写处理说明，再点击“确认已修复”。服务器要求当前音频已更新且文本哈希与当前公开发音一致，旧音频不能当作修复结果；系统无法自动判断实际读音是否正确，仍需人工试听。无需修复或词条已封禁时，填写原因并关闭，用户可以查看说明。

## 数据与接口

- `V19__audio_feedback.sql` 为新增迁移，保留全部旧迁移；数据库字段有中文注释，业务操作使用 Spring Data JPA。
- `GET /api/v1/audio-feedback` 只返回本人反馈，可按 `entryId`、`resourceId`、`kind` 和 `page` 筛选。
- `POST /api/v1/audio-feedback` 必须携带 CSRF 和 `X-Learning-Account`。客户端 UUID 固定提交内容，同一请求重试不重复入库；更换正文须使用新的 UUID。
- `GET /api/v1/admin/audio-feedback` 支持 `status` 和 `page`；`GET /{id}` 返回问题和当前公开资源。
- `POST /api/v1/admin/audio-feedback/{id}/regenerate` 接收反馈 `version`；云调用在事务之外，不自动结单。
- `POST /api/v1/admin/audio-feedback/{id}/resolve` 接收 `version`、`status`（`RESOLVED` 或 `DISMISSED`）、`note`，必须带 CSRF 和当前管理员账号头。

普通用户不能查询或处理后台反馈，管理员不通过反馈读取私人词条、邮箱、云对象键或学习记录。反馈不更新 FSRS。注销账号时通过外键级联删除本人提交的反馈和说明，其他用户的反馈及公开词典保留。审核版本防止陈旧表单覆盖；相同处理人、相同最终结果的网络重试保持幂等。

## 手动验证

1. 登录，打开含发音的公开词条。分别对词条和例句提交反馈，刷新弹窗应能看到自己的记录。
2. 使用普通账号尝试后台接口，应被拒绝；切换账号后不应看到原账号的反馈记录。
3. 管理员进入“发音反馈”，打开记录。未配置 Google/R2 时重新生成提示配置缺失，点击“确认已修复”应被拒绝，原反馈仍为待处理。
4. 填写核对结果后选择“无需修复并关闭”。提交人刷新弹窗应看到结果和说明。
5. 配置实际云服务后，修正、发布、生成和试听，再确认已修复；失败不能覆盖原音频或误结单。
6. 手机宽度390px核对弹窗、说明和列表；页面离开或切换账号时弹窗应关闭。

真实云发音质量仍需配置 Google/R2 后试听。自动化测试中的云替身仅用于验证生成失败、新版本和权限边界，不作为正式发音内容。
