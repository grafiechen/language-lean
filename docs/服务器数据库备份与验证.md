# 服务器数据库备份

更新日期：2026-10-06。开发分支：`feature/database-backups`。

本功能属于服务器灾备，个人学习数据导出仍然关闭。后台不提供数据库文件下载、解密密钥、连接地址或生产恢复按钮。当前默认关闭，不调用R2，不修改生产部署、域名或DNS。实际部署连接、密钥和日志只保存到项目外的私有运维记录，本文仅描述通用配置与流程。

## 配置与入口

`/admin` → “系统用量” → “服务器数据库备份”显示配置及最近30个执行记录。只有ADMIN能读取或触发任务，手动请求受CSRF保护并绑定当前会话管理员。服务关闭或配置不完整返回503，普通用户无权访问。任务排队后页面短暂轮询，离开页面停止轮询及旧响应回写。未确认响应的重试沿用请求UUID，不重复创建转储。

服务器环境配置项：

| 配置 | 默认 / 含义 |
| --- | --- |
| `BACKUP_ENABLED` | `false`，完全关闭转储、上传和云清理 |
| `BACKUP_INTERVAL_HOURS` | `0`，不自动定时；正整数表示间隔小时，最大8760 |
| `BACKUP_RETENTION_DAYS` | `0`，不自动删除成功备份；正整数最多36500天 |
| `BACKUP_TIMEOUT_SECONDS` | `1800`，转储超时；支持30至3600秒 |
| `BACKUP_ENCRYPTION_KEY` | 独立随机32字节的Base64密钥，必须私下保存，禁止提交或设为VITE变量 |
| `BACKUP_KEY_ID` | 非秘密的密钥版本标识，1–80个字母、数字、下划线或短横线 |
| `R2_BACKUP_ACCOUNT_ID` | 备份存储账户标识，32位十六进制 |
| `R2_BACKUP_ACCESS_KEY_ID` / `R2_BACKUP_SECRET_ACCESS_KEY` | 仅用于独立私有备份桶的服务器凭据 |
| `R2_BACKUP_BUCKET` | 私有备份桶名称，不复用音频播放入口 |
| `BACKUP_WORK_DIRECTORY` | 默认`/tmp/language-lean-backups`，只暂存加密文件 |

数据库连接沿用API的服务端配置；当前转储支持无查询参数的`jdbc:postgresql://host:port/database`，库名为字母、数字、下划线或短横线。不接受浏览器指定数据库或转储命令。配置状态只证明字段与客户端齐备，不能证明云服务已经连通。

普通后端镜像保持轻量；备份使用可选 [Dockerfile.backup](../backend/Dockerfile.backup)，包含PostgreSQL17工具和Java21 JRE。使用 `docker compose -f compose.yml -f compose.backup.yml build api` 构建；部署时实际私有配置、镜像路径和挂载位置由项目外运维记录提供。本次只验证本地Docker架构，尚未部署OCI。

R2桶必须保持私有，不创建公共域名、公开链接或浏览器凭据。要开启时先配置独立桶、备份密钥和对应镜像，再设置开关。频率和保留规则尚未获得具体确认，所以默认不定时、不自动清理成功归档。

## 任务和归档

Flyway V22增加 `database_backup_job`、`database_backup_control` 和 `database_backup_object`。任务记录管理员UUID、触发方式和时间，错误仅保存固定错误码；对象记录密文大小、SHA256、密钥版本标识及清理状态。数据库不存明文备份密钥，版本标识不能用于解密。

单行JPA悲观锁控制跨进程串行认领，所有事务保持短暂，转储和云请求不持有状态行锁。工作者有租约和认领令牌；过期或中断任务标记失败，旧工作者无法确认成功。迟到上传再次登记清理。专用工作线程执行IO，系统调度线程不会被长时间备份占用，一次性密码密钥仍可过期清理。

`pg_dump`使用压缩自定义归档，提供一致的数据库快照。输出直接进入分块AES-256-GCM流，不在磁盘写明文数据库。排除一次性密码传输密钥和邮件重置凭证的表数据，但保留其表结构。归档包含账号及学习数据、公开词典和迁移历史；不包含音频云文件、Docker卷物理镜像、SMTP/R2凭据或服务器环境配置。

每次归档产生96位随机基础IV，每块通过块序号派生不同IV；头部、块序号和明文块长度均参与认证。64KiB块限制内存使用，独立认证的终止块防止截断，额外尾部数据也会被拒绝。头部包含格式版本、密钥版本标识、基础IV、归档格式和块大小，不含连接或密钥值。

归档仅在转储退出成功后上传。上传后完整回读，核对密文大小和SHA256，一致后才标记SUCCESS/VERIFIED。上传或核验失败不产生“可恢复”的成功记录，可能已存在的对象进入清理队列；网络失败会留下记录重试。固定对象键在上传前写入数据库，存储账户及桶的摘要用于防止换桶后误清理。

保留期大于0时，只清理已验证且超期的对象，并始终保留当前存储范围最新的一份已验证归档。失败的孤立对象不按成功备份保留；执行记录不随归档清理删除。定时任务按执行时刻推进下一次时间，不为漏过的间隔创建大量补跑任务。应用停止或严重故障期间没有备份保证，配置开关不等于备份已经成功。

## 独立运维验证与恢复

备份密钥与密码请求的两分钟临时密钥是不同用途。历史归档需要对应的历史备份密钥，轮换时必须保留仍需恢复的旧版本；本功能不自动删除或过期历史解密密钥。密钥应由服务器或运维环境安全随机生成并私下保存，例如使用`openssl rand -base64 32`重定向到受限私有文件，不能打印到聊天或提交仓库。

离线命令使用私有环境文件传入`BACKUP_KEY_ID`和`BACKUP_ENCRYPTION_KEY`。创建命令另外需要服务端`DB_URL`、`DB_USER`和`DB_PASSWORD`。命令不打印密码、连接或密钥，不启动Web服务：

```sh
# 在备份镜像中创建新加密归档，目标不能已存在。
java -Dloader.main=com.languagelean.operations.backup.BackupArchiveCommand \
  -cp /app/app.jar org.springframework.boot.loader.launch.PropertiesLauncher \
  --create /private-backups/new.llbackup

# 解密到新的私有文件；完整认证通过后才发布结果。
java -Dloader.main=com.languagelean.operations.backup.BackupArchiveCommand \
  -cp /app/app.jar org.springframework.boot.loader.launch.PropertiesLauncher \
  /private-backups/new.llbackup /private-backups/validated.pgdump
```

私有目录须由镜像运行用户UID10001拥有，权限建议0700，文件为0600。解密拒绝错误密钥、错误版本标识、头部篡改、块乱序/重复/缺失、截断和附加数据；认证失败删除暂存，已有目标文件不覆盖。

恢复验证必须使用独立空数据库，先核对归档SHA256、密钥标识及来源，再认证解密并使用 `pg_restore --exit-on-error --no-owner --no-acl`。核对业务数据、账号、迁移历史以及两类临时凭证表为空。完整生产恢复还需停写、核对镜像版本、服务器私有配置、音频对象和中断任务状态，属于单独的运维操作；本功能不会自动恢复生产、覆盖现有学习数据或把历史凭证重新激活。

## 验证证据

本地后端完整150项测试、前端完整136项测试及前后端容器构建通过；备份镜像中的Java21与PostgreSQL17工具实际启动成功，V22在真实临时PostgreSQL执行成功。该证据覆盖本地代码与灾备格式，不能替代真实R2和生产环境演练。

加密归档单元测试覆盖大于一个块的文件、空文件、随机密文、错误密钥、头部认证、乱序、重复、缺失、截断、附加数据和已有文件保护。备份集成测试覆盖默认关闭、幂等、并发串行、失败释放、孤立文件重试、保留最新归档、存储范围隔离、过期工作者和定时频率。真实R2适配器通过SDK替身验证完整回读、相同大小但不同内容、截断和超长对象；没有连接真实R2。

独立临时PostgreSQL17使用真实`pg_dump`、本格式加密、完整认证解密及`pg_restore`完成往返，中文内容、账号和V22迁移历史恢复一致。转储前两类临时凭证各有一条，恢复后均为零。Chrome验证默认关闭时历史记录仍可显示、成功/失败提示、无下载入口以及390px布局无横向溢出。浏览器执行记录展示使用测试元数据，不代表真实云上传已验证。

依据：[PostgreSQL pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html)、[PostgreSQL Backup and Restore](https://www.postgresql.org/docs/17/backup.html)。当前代码及本地验证完成后仍需配置真实私有R2、确定保留策略并完成云端灾备演练，才能宣称生产备份可用。
