# 词典导入格式与实际测试

## 当前入口

系统词典导入只允许管理员操作。导入分为两个动作：

1. 上传并校验：文件进入暂存批次，检查 UTF-8、格式、语言、内容完整性和重复身份，不修改公开词典。
2. 确认并发布：只发布预览中标记为“可导入”的新词条，每个词条形成第 1 个公开版本。

数据库已有相同 `languageCode + scriptCode + NFKC(written)` 的词条时，页面显示“基准词典中已存在，已跳过且不会覆盖”。同一个文件中重复出现时显示“文件内重复，已跳过”。预览之后、确认之前新出现的重复也会再次检查并单独计数。

## 自己在浏览器中测试

1. 在项目根目录启动开发环境：

   ```powershell
   wsl -d Ubuntu -- bash -lc 'cd /mnt/d/gitHome/language-lean && docker compose -f compose.dev.yml up -d'
   ```

   如果命令结束后容器也停止，请去掉末尾的 `-d` 并保持该终端窗口运行。本机当前已用前台模式启动，无需重复执行。

2. 打开 http://localhost:5173，使用 `.env` 中配置的管理员用户名或邮箱登录。
3. 进入“后台词典管理”→“批量导入”。
4. 点击“下载测试示例 JSON”，再选择该文件并点击“上传并校验”。
5. 第一次使用空词典测试时，应看到总数 3、可导入 3、已存在 0、无效 0。若之前手工创建过猫、犬或学ぶ，对应行会显示“已存在”，这是正常结果。
6. 点击“确认并发布可导入词条”。确认完成后打开“查看用户词典”，分别搜索猫、犬、学ぶ。
7. 回到导入页重新上传同一个文件，三个词条都应显示“基准词典中已存在”，并且按钮不会覆盖原内容。

要测试错误提示，可以复制示例文件并做以下任一修改：

- 复制一个完整的 `entries` 元素，验证“文件内重复”。
- 把 `gloss` 改为空字符串，验证“释义不能为空”。
- 把 `scriptCode` 改成 `jpan`，验证 ISO 15924 四字母格式。
- 用非 UTF-8 编码保存文件，验证编码拒绝。

测试完成后可直接保留这些公开词条；当前公开词条不提供硬删除。如果不希望测试数据进入本地正式数据卷，只执行上传预览，不点击确认，或者使用单独的 Docker Compose 项目和数据库卷。

## 规范化 JSON 契约

仓库内的可直接上传示例位于 `frontend/public/examples/dictionary-import.sample.json`。顶层格式如下：

```json
{
  "schemaVersion": 1,
  "source": {
    "name": "词典名称",
    "version": "数据版本",
    "license": "许可证标识"
  },
  "entries": []
}
```

每个词条支持：

```json
{
  "languageCode": "ja",
  "scriptCode": "Jpan",
  "written": "猫",
  "readings": [
    { "reading": "ねこ", "pronunciationText": "ねこ" }
  ],
  "senses": [
    {
      "partOfSpeech": "名词",
      "gloss": "猫",
      "examples": [
        {
          "text": "猫がいる。",
          "pronunciationText": "ねこがいる",
          "translation": "有一只猫。"
        }
      ]
    }
  ]
}
```

- 文件必须是严格 UTF-8 JSON，单文件最多 10 MB、5000 个词条。
- `source.name`、`source.version`、`source.license` 必填，发布后写入内容版本。
- `languageCode` 必须已经在后台语言配置中存在且启用。
- `scriptCode` 使用 ISO 15924 四字母形式，例如 `Jpan`、`Latn`、`Hans`。
- `written` 和至少一个非空 `gloss` 必填；读音和例句可为空数组。
- 上传格式不接受内部 UUID。服务端在暂存时为读音、词义和例句生成稳定 UUID，并在确认时使用同一份规范化快照。

## 原始开源词典

后台入口接收规范化 JSON，不直接解析 JMdict XML、JMnedict、KANJIDIC 或其他来源原始文件。仓库已经为第一本基准词典接入 EDRDG `JMdict_b`：`tools/jmdict_to_postgres.py` 流式解析官方 XML 压缩文件，并生成可重复执行的 PostgreSQL 初始化 SQL。原始文件、生成清单和安装说明见 `data/jmdict/README.md`。

JMdict初始化SQL独立于Flyway结构迁移，当前文件要求先完成V1—V16。SQL使用稳定UUID和冲突跳过，重复执行不覆盖人工词条或已有发布版本，并登记源版本、SHA-256、许可和实际词条数。基准安装后执行保存的例句补充SQL，以追加发布版本保留历史；说明见[母语译文与例句导入](./母语译文与例句导入.md)。个人CSV入口与公开词典JSON导入分开，见[个人CSV导入与测试](./个人CSV导入与测试.md)。

其他来源仍需先确认版本和许可要求，再编写对应适配器，将字段、词性代码和限制条件转换为业务内容快照。不要把来源不明或许可证不兼容的数据导入公开基准词典。

## 自动验证

完整容器构建会执行后端集成测试和前端测试：

```powershell
wsl -d Ubuntu -- bash -lc 'cd /mnt/d/gitHome/language-lean && docker compose build api web'
```

导入集成测试覆盖普通用户被拒绝、文件内重复提示、确认前公开查询不可见、确认后发布、无效项隔离，以及再次上传时提示数据库中已存在。
