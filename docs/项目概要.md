## 1. 项目背景

Language Lean 是一个配合纸质单词本使用的个人语言学习工具。

项目当前首先解决日语学习中的一个具体问题：有些单词看到文字时认识，但在真实听力中听到发音时不能及时识别。这类词在本项目中称为“耳词”或“假生词”。

纸质单词本继续承担书写、整理和视觉记忆；本系统主要承担发音生成、听觉回忆、复习调度和耳词强化，不试图在第一版替代完整的语言教材或纸质学习流程。

## 2. 产品目标

第一阶段的核心目标是建立以下闭环：

```text
录入日语单词和例句
→ 生成并保存高质量 TTS
→ 隐藏文字播放单词
→ 用户回忆词义
→ 显示答案
→ 用户选择 × / △ / ○
→ 系统安排下次复习
→ 听觉薄弱词进入耳词池
```

长期目标是在相同账户、词库和复习基础设施上，逐步增加文字背词、词形变化、造句训练和其他语言。

## 3. 第一版范围

### 3.1 账户与权限

- 系统支持多账户。
- 保留用户注册能力，但第一版关闭公开注册入口。
- 第一版账号仅由管理员在后台创建。
- 角色暂定为 `ADMIN` 和 `USER`。
- 普通用户只能访问自己的个人数据，以及已发布的系统词典和用户贡献词条。
- 管理员可以创建、启用、禁用和删除账号，并管理系统配置、词典审核和用量。
- 管理员默认不查看用户的具体学习内容。
- 第一版支持同一账户多设备同步和断网学习。
- 创建账户时用户名、邮箱均必填，登录时两者任选其一。初始密码通过邮件发送，找回密码也走邮件渠道；登录态修改密码填写原密码、新密码和重复新密码。
- 注销账户彻底删除个人内容和学习数据；相同邮箱或用户名重新创建账户使用新的用户 ID，不关联旧数据。

### 3.2 语言配置

- 第一版只实现并启用日语 `ja-JP`。
- 前端不得硬编码可用语言列表。
- 前端从后台接口获取当前启用的语言及其功能入口。
- 页面顶部保留语言上下文区域；只有后台启用多种语言后，才提供实际切换能力。
- 当前语言决定单词本、词性、训练入口、TTS配置和学习进度范围。
- 每个单词本只属于一种学习语言，不在同一个单词本中混合语言。
- 后续语言如果无法与日语共用特定功能，可以使用独立语言模块实现。

### 3.3 单词与例句管理

第一版支持：

- 手动逐个创建或引用词条。
- 使用 CSV 批量导入个人学习条目。
- 查看、修改和删除个人学习条目。
- 检测重复学习条目。
- 为词条填写或引用一个或多个例句。
- 分别生成单词和每条例句的音频。

个人学习条目引用公开基准词条或自己的个人词条。个人词条与公开基准词条是不同实体；用户可以保存个人释义、读音等覆盖内容，未覆盖部分沿用基准内容。个人修改和删除不改变基准词典。用户标签、笔记、复习状态和耳词状态属于用户自己的数据。

用户可以创建单词本分类和选择复习范围，同一词跨单词本共享一份进度。从一个单词本移除时仅删除关联；最后一个单词本移除时彻底删除对应个人学习条目、进度与历史，重新加入从零开始。主动删除个人学习条目同样不保留其个人内容和进度。

提供按范围重置学习进度的功能，清除范围内全部学习进度信息并从零开始，保留词条内容和分类。同一词在其他单词本的共享进度也随之重置。

CSV 基础格式暂定为：

```csv
該当,がいとう,符合,N2
```

个人CSV已采用兼容以上无表头示例的固定列顺序，额外可选例句、例句发音和译文；模板、预检及重复处理见[个人CSV导入与测试](./个人CSV导入与测试.md)。

基础信息包括：

- 单词或表达。
- 发音标注；日语第一版对应假名。
- 中文释义。
- 所属单词本。
- 语言。
- 系统词性。
- 自定义标签。
- 例句及例句释义。

重置单词本时完整清除其中所有词的 FSRS、复习历史、自动耳词状态及手动重点，恢复初始未学习状态；其他单词本引用的同词共享进度也归零。保留词条内容、个人内容覆盖和单词本关联；旧草稿与待提交进度通过重置代次隔离，不能恢复已清除的状态。

### 3.4 分类与标签

系统分类和自定义标签必须分开。

系统分类会影响后续训练能力。日语计划支持：

- 名词。
- 动词：一类、二类、不规则。
- 形容词：い形容词、な形容词。
- 副词。
- 助词。
- 接续词。
- 表达及其他类型。

自定义标签只用于用户整理，例如：

- N1、N2。
- 工作、新闻、易错。
- 纸质本页码或章节。

第一版需要保存这些分类信息，但动词和形容词变形训练属于后续迭代。

### 3.5 听觉测试

基础交互为：

```text
进入测试
→ 页面不显示答案
→ 自动播放单词的主要读音
→ 用户进行回忆
→ 点击“显示答案”
→ 显示单词、假名、中文释义和例句
→ 用户选择 × / △ / ○
→ 自动进入下一题
```

评分含义：

- `×`：完全没有听出来。
- `△`：模糊、反应较慢或主要依靠猜测。
- `○`：能够较快、明确地识别。

测试页面还需要提供重新播放能力。答案显示前不得通过文字、假名或其他信息泄露答案。

第一版同时提供例句音频。例句音频不默认播放；用户点击哪个音频，就只播放哪个音频。单词音频与例句音频相互独立。

一个词条可以有多个读音。普通测试默认播放主要读音；耳词训练可以轮播多个读音。轮播只属于展示和训练内容，不创建额外学习状态。

### 3.6 遗忘曲线

- 系统根据每次 `× / △ / ○` 使用 FSRS/DSR 自动安排下一次复习。
- FSRS 状态只属于“用户 + 个人学习条目”，不属于系统词典。
- `×` 和 `△` 通常会缩短复习间隔，连续 `○` 通常会延长复习间隔。
- 第一版评分映射暂定为：`× → Again`、`△ → Hard`、`○ → Good`；暂不增加 `Easy` 按钮。
- 每次复习必须保留复习事件、评分、复习前后状态、算法版本和下次复习时间。
- 目标保留率、初始学习步骤和 FSRS 具体版本在调度模块开发前确认。
- 到期词优先于新词；未到期词可以额外训练，额外训练同样更新 FSRS。
- 不设置每日数量或配额，选定范围内有多少待复习词就提供多少，到期优先；每组最多 10 词不限制每日总量。
- 第一版只有听音回忆自评。未来同一个词条该轮所选复习类型全部完成，才计为一次完整复习并更新共享 FSRS；任意类型未完成则仅保存本地草稿，不计为完成。多类型分别评分，取最差的 × / △ / ○ 作为最终评分，只更新一次 FSRS。
- 题型可扩展性从第一版设计和编码时落实：使用题型注册表与适配器、统一复习轮次、逐项结果及版本化协议。听音回忆是第一个适配器，题型交互不直接更新 FSRS 或上传；未来增加题型复用完成判定、最差评分聚合与同步流程。具体契约见设计文档 4.4 节。
- 多题型训练按每组最多 10 个词分组，先完成本组全部词的 A 题型，再进行 B、C，整组完成后进入下一组。某词选 Again 时该题型未通过，自动追加到剩余队列队尾重试，直到 Hard 或 Good；失败尝试仍参与最差评分，因此重试通过不抹掉 Again。每词全部题型完成后仅更新一次 FSRS 并立即上传。第一版实现分组与队尾重试调度，多题型阶段保留扩展能力，具体见设计文档 4.5 节。

第一版听音回忆也每组最多 10 词，Again 后穿插其他词重试至 Hard/Good，最终评分取全部尝试的最差值，只更新一次 FSRS。

### 3.7 耳词池

- 听觉测试选择 `×` 或 `△` 时，单词自动进入耳词池。
- 用户也可以手动将单词加入耳词池或取消手动重点状态。
- 耳词池提供独立训练入口。
- 耳词不会因为连续几次 `○` 被直接删除。
- 耳词仍由遗忘曲线调度：薄弱时高频复习，稳定后进入低频保持；以后再次答错时恢复高频复习。
- 耳词仍使用同一份 FSRS/DSR 状态；多读音轮播不创建多份状态。
- 正常学习期间保留耳词历史和复习记录；用户删除、重置进度或注销时按相应范围清除。

### 3.8 同步与本地使用

每次点击判定立即保存尝试和队列，Again 自动排到剩余队列队尾，仅剩该词也自动成为下一题，不需要再次测试按钮。退出后从本地草稿继续。默认当日清单按 FSRS 到期时间生成，未到期词不出现，新词按初始调度处理，额外训练入口保留。

缓存按服务端实例和稳定用户 ID 隔离，允许多账号；登录过期仍可在原账号分区离线学习，重新登录对应账号后才能上传其记录。服务端确认逐条接收后清理对应待提交记录和已完成草稿，未确认记录保留；离线词条、音频、当前进度及其他未完成草稿不清空。具体数据结构见设计文档 9.1。

第一版提供离线准备，缓存应用页面、选定范围学习内容及音频，支持断网关闭后重新打开；区分未准备、准备中、已准备和部分失败。无发音词保留在单词本，标记待补充发音，不入听力队列。重置切换进度代次，旧代次草稿和事件不能恢复进度；删除后重新加入使用新的学习条目 ID，并保留最小同步删除标记。

- 第一版必须支持断网学习。客户端预先保存学习内容、个人状态和音频，本地持久保存复习结果，联网后重试同步。
- 每个词条完成后立即尝试上传，不等待整批学习结束；选择多个复习类型时须全部完成后上传一次词条进度。
- 提供“上传今日学习进度”，手动补传今日已完成但上传失败/未确认的记录。未完成的轮次不上传为完成；重试使用相同事件 ID 避免重复计分。跨日未上传记录仍保留并通过常规重试或全账户同步处理。
- 每次复习提交保存基准版本、本次版本和幂等事件 ID。多设备当前进度以实际答题时间最后的一次提交为准，不以上传到服务器的先后为准；迟上传的旧答题不覆盖新进度。
- 版本优先考虑时间戳，但事件 ID 独立；时钟偏差、同时间戳冲突及删除/重置后旧事件隔离的细节在同步协议中确定。
- 打开某个单词页面时，只同步当前单词及其相关内容，不自动全量同步。
- 页面提供手动同步按钮；手动同步作用于当前账户的全部个人数据。
- 音频按单个文件独立检查和更新，不进行全库缓存失效。
- JSON 备份至少包括词典引用、用户词条、例句引用、分类、标签、复习状态、耳词状态和音频版本信息。
- JSON导出暂缓开放；同账号已有JSON备份的本机恢复继续保留。

### 3.9 用户贡献词典

用户创建自己的个人词条，与公开基准词条分开存储并按用户去重。申请贡献时生成 `PENDING_REVIEW` 审核申请；经管理角色审核通过且公开后才录入基准词典。之后个人修改、删除不影响已发布的基准内容。

公开词条修改也需审核。待审期间查询旧版，审核发布后查询新版；数据库保存线性历史版本，支持追加版本方式回退和纠错。公开条目被封禁或删除后，已有引用显示“已封禁”或“已删除”。

用户个人标签、笔记、学习记录和私人例句不因词条公开而自动公开。

## 4. TTS需求

### 4.1 当前服务

- 第一版使用 Google Cloud Text-to-Speech 的 Chirp 3 HD。
- 当前语言为日语 `ja-JP`。
- 每种语言分别配置TTS服务商、模型、语言代码和固定默认声音。
- 第一版日语只使用一个固定声音，不为每个用户生成不同音色版本。
- TTS只能由服务端调用，客户端不能获得Google服务凭据。

### 4.2 生成对象

保存时自动生成缺失音频；联网打开单词详情发现未生成时补生成。同一内容的生成需要互斥锁，获取锁后再次检查音频和已有任务，防止同时打开造成重复生成。单例服务对象仍需配合锁与任务去重。个人音频自动生成在后台管理页面配置，当前默认开启。

点击词条发音或例句音频时，同样检查对应音频是否生成成功且可用；未生成或此前生成失败时调用统一补生成流程，成功后播放，已有任务则复用。词条或例句没有填写发音时跳过生成，不自动用正文替代缺失发音；此条件适用于所有生成入口。例句需支持可选发音文本，缺失时仍允许保存和查看。

断网只能使用已缓存音频，不能即时调用服务端 TTS；缺失或生成失败必须显示状态，不静默跳题或记分。离线准备的缓存范围与交互待细化。

- 单词音频。
- 每条例句的独立音频。
- 后续可以增加搭配、变形和其他训练音频，但不属于第一版。

音频存在但读错时，用户修改个人发音后重新生成；公共音频提交问题反馈，由管理员修正并重新生成。

### 4.3 音频版本

每个音频文件拥有独立版本。修改或重新生成某个音频时：

- 只增加该文件的版本。
- 不影响同一单词的其他例句音频。
- 不影响其他单词。
- 新文件上传成功后才切换当前版本。
- 新版本失败时旧版本继续可用。

音频需要记录：

- 所属语言。
- 服务商、模型和声音。
- 生成文本或文本哈希。
- 独立版本号。
- 文件哈希。
- 对象存储路径。
- 生成状态。

### 4.4 保存原则

```text
Spring Boot调用Google TTS
→ 接收生成结果
→ 立即上传Cloudflare R2
→ 上传成功后保存音频元数据
→ 不在Oracle服务器长期保留MP3
```

## 5. Cloudflare存储与托管

### 5.1 R2用途

计划使用两个逻辑隔离的存储空间：

```text
音频存储：单词和例句MP3
私有备份：PostgreSQL备份文件
```

- 音频生成后立即进入R2。
- PostgreSQL定时导出、压缩并备份到私有R2。
- 公开音频与私有数据库备份不能共用访问权限。
- 所有bucket共享Cloudflare账户的免费额度，并非应用内每个用户各有10GB。
- 当前R2 Standard免费额度为每月10 GB-month存储、100万次Class A操作、1000万次Class B操作，出口流量免费；价格和额度上线前需再次核对。

### 5.2 前端托管

- Vue构建产物计划部署到Cloudflare Pages。
- Pages负责前端静态资源和全球分发。
- 前端不必占用Oracle实例资源。
- API和音频使用独立子域名。

## 11. 词典底层模型（当前确认版）

### 11.1 基本原则

词典内容分为三类：

~~~text
公开基准词条：管理员维护，包含开源导入与审核公开的用户贡献
贡献审核申请：提交内容快照，审核发布前不改变公开内容
个人词条与覆盖：按用户隔离，允许完整内容，也允许未解析内容
~~~

系统词典是全局只读知识库。普通用户只能查询、引用和基于词典创建个人学习数据，不能修改系统词典。管理员通过导入、审核、修订和发布新版本维护系统词典。

第一版以 EDRDG 的 JMdict 基础版 `JMdict_b` 为开源基础词典；后续可以追加其他来源导入，也允许管理员手工录入。

2026-10-04已按用户确认补充Tomoshi 2026-09-02的简繁中文释义，在同一JMdict全局身份上追加206,826个词条版本，覆盖现有208,684个词条约99.1%。译文保留Y1Z、EDRDG、CC BY-SA 4.0及机器翻译经模型校订说明；后续可在后台或投稿审核中人工修订。原英文、日语发音、现有例句和学习进度保持不变；版本错位或缺失继续英文回退，具体部署SQL及保护规则见[Tomoshi数据说明](../data/tomoshi/README.md)。

继续补充Jitendex社区中文版的29,691条简体中文例句译文，保留原有1,245条中文，在31,527条精选例句引用中达到约98.1%中文覆盖。仅精确匹配已有日文原句及Tatoeba身份，不创建重复例句；来源机器翻译经模型校订，跳过待核及冲突，仍支持人工修订。部署种子及许可见[Jitendex例句说明](../data/jitendex/README.md)。

词典需要区分以下对象：

```text
字符 Character
WordEntry
  written                 // 固定的基准写法
  ├─ Pronunciation[]      // 一个或多个读音
  ├─ Sense[]              // 一个或多个词义
  ├─ GrammarFeature[]     // 词性和语法属性
  ├─ ExampleSentence[]
  ├─ InflectedForm[]      // 活用或派生形式
  ├─ 多词表达与组成关系
  ├─ 词义级词汇关系
  └─ 来源、许可证、质量状态和版本
```

基准词条以一个固定的书写形式为身份。相同书写形式只建立一个基准词条；读音、词义、词性和例句都是该词条下的内容。不同书写形式不因读音或释义相同而合并。

公开基准词条（含已审核公开的贡献）的唯一键为；个人词条另外按用户隔离，不占用此唯一键：

~~~text
language + script + normalized_written
~~~

异体字或其他书写变体如果需要关联，应建立单独条目并使用关系连接，而不是在一个基准词条中保存多个主写法。

复合词（如「今日」「大人」）作为独立基准词条保存自己的读音和含义，同时可以通过组成关系关联「今」「日」等组成单位，不能根据单字读音简单拼接。

### 11.2 读音、词义与排序

同一个基准词条可以有多个读音和多个词义。每个读音和词义至少保存：

~~~text
is_primary
display_order
quality_status
source
version
~~~

is_primary 控制默认展示和播放；display_order 控制页面顺序。常用程度、频率和地区等外部标注单独保存，不直接等同于手工展示顺序。

近义词、反义词、相关词、自动词/他动词等关系绑定到具体词义；如果关系只适用于一个词义，不能只绑定整个词条。

### 11.3 标准例句

标准例句属于系统词典内容，但例句本身是独立实体。例句主要按具体词义分组：

```text
WordEntry
  └─ Sense
      └─ SenseExample
          └─ ExampleSentence
```

一个词义可以有多个标准例句；一条例句也可以关联多个词义，但应设置 `PRIMARY` / `SECONDARY` 关系，默认只在主要词义下展示。

标准例句需要支持：多语言翻译、来源和许可证、难度、正式程度、地区、使用频率、标准音频及独立版本号。用户例句单独存放，不能修改标准例句。

例句录入或导入时完成分词、词形还原和词典匹配，并保存派生结果：

```text
ExampleSentence
  └─ ExampleTokenization
      └─ ExampleToken
          └─ TokenEntryCandidate
```

前端点击例句中的词语时，使用已保存的token和词典ID直接打开词典卡片。分词结果需要记录分析器版本和词典版本；原始例句保持不变。

### 11.4 语言通用核心与语言扩展

通用核心适用于日语、英语和汉语：基准词条、词形、发音、词义、释义、例句、词汇关系、来源和版本。

语言专属内容放在语言扩展中：

- 日语：汉字、平假名、片假名、读音限制、熟字训、五段/一段/サ变/カ变、自动词/他动词、助词和活用。
- 英语：英美拼写、IPA和地区发音、单复数、过去式、过去分词、比较级、不规则形式、及物性和短语动词。
- 汉语：简体/繁体、普通话和方言读音、拼音声调、量词、离合词以及地区用法。

词典语言、文字脚本、发音locale、释义语言和TTS语言分别保存，不使用一个字段混合表示。

### 11.5 规则变形与不规则变形

符合标准规则的词，保存语言属性和规则类别，由统一规则生成变形：

```json
{
  "entryId": "entry_xxx",
  "language": "ja",
  "partOfSpeech": "VERB",
  "conjugation": {
    "mode": "RULE",
    "ruleClass": "GODAN_KU",
    "ruleVersion": 1
  }
}
```

生成的词形记录语法特征和规则版本：

```json
{
  "formType": "TE_FORM",
  "written": "書いて",
  "reading": "かいて",
  "generated": true,
  "ruleVersion": 1
}
```

不符合通用规则的词，明确标记为特例并保存覆盖结果：

```json
{
  "entryId": "entry_xxx",
  "language": "ja",
  "partOfSpeech": "VERB",
  "conjugation": {
    "mode": "OVERRIDE",
    "ruleClass": "GODAN_KU",
    "irregular": true,
    "overrides": [
      {
        "formType": "TE_FORM",
        "written": "行って",
        "reading": "いって",
        "reason": "IRREGULAR"
      }
    ]
  }
}
```

优先级为：词条特例覆盖 → 语言特殊规则 → 通用规则。一个语法形式可以允许多个正确结果，并保存说明、来源和版本。

### 11.6 用户学习数据与系统词典的边界

词条采用全局唯一稳定 ID；合并保留旧 ID 到规范 ID 的映射，按规范身份在用户范围内复用同一学习条目、进度和单词本关联，保留个人覆盖。全局 ID 不替代写法去重，不改变个人内容权限。

公开基准词典只提供内容，用户学习域保存引用、个人内容覆盖和个人状态：

~~~text
UserLearningItem
  user_id
  dictionary_entry_id
  wordbook_memberships
  fsrs_state
  ear_word_state
  review_history
~~~

一个词条可以被多个用户引用；每个用户的 FSRS/DSR 状态完全独立。一个词条有多个读音或多个词义时，仍然只对应一份用户学习进度。读音和词义只影响页面展示、音频选择和例句关联。

### 11.7 查询与例句点击

查询接口统一，但具体分析按语言实现：

```text
输入
  → Unicode规范化和语言处理
  → 精确文字/读音查询
  → 变形还原
  → 文字变体和发音别名查询
  → 模糊匹配
  → 返回候选词条、读音、词义和匹配类型
```

日语搜索支持汉字、平假名、片假名、复杂变形和多音字；英语支持不规则形式和英美拼写；汉语支持简繁、拼音和多音字。

候选优先级为：

~~~text
精准系统词条
→ 精准用户贡献词条
→ 精准个人词条
→ 模糊匹配
~~~

每一层内部使用动态 score 排序。系统词典、用户贡献词条和个人词条的来源优先级不能被模糊匹配分数随意逆转。语言分析和词形还原由应用层完成，PostgreSQL负责索引、候选筛选和排序。

### 11.8 来源、版本和派生数据

原始来源、规范词典数据和派生索引分开保存：

```text
原始来源数据 → 规范词典数据 → 分词/变形/搜索索引/音频
```

导入内容先进入暂存区，经格式校验、去重、冲突检查和管理员审核后发布。相同书写形式的基准条目不重复创建；新读音、新词义和新例句作为同一条目下的待审核补充，不覆盖已有内容。词条、读音、词义、变形和例句都有自己的质量状态。

词典更新不能覆盖用户学习记录。合并、拆分、替换和停用通过迁移关系保持旧ID可追踪。JLPT、HSK、CEFR、频率、地区和语域属于独立标注，不直接写死在词条核心中。

### 11.9 用户贡献词条与个人未解析词条

普通用户可以创建自己的词条，包括与公开词典相同的写法；个人内容可以独立修改。贡献申请与公开条目分开，申请保存提交快照和审核状态，已公开条目记录来源及发布版本：

~~~text
origin_type: USER_CONTRIBUTED
created_by_user_id
visibility
moderation_status
source
license
current_revision_id
~~~

贡献申请默认进入 `PENDING_REVIEW`；审核通过且公开后录入基准词典，创建者在审核期间继续使用自己的个人词条。公开词条保留线性版本和封禁/删除标记；个人词条可以彻底删除，不改变公开条目。

如果用户只记录了写法而暂时没有读音或释义，可以先建立个人未解析学习项，补充后申请贡献。发布时创建公开条目或修订已有公开条目，个人内容与公开内容仍是不同实体；发布不会清空学习进度。

### 11.10 字符与编码

字符层独立于词典词条层，用于保存 Unicode 码点、字符读音、部首、笔画、简繁关系、日语音读/训读及其他字符属性。

数据库、JSON、HTTP 和导入后的统一存储使用 UTF-8。当前不把 Unicode 新版本升级作为业务功能；保留原始文字、字符码点和规范化搜索键即可。编码支持与字体显示分开处理，数据库能保存字符不代表所有客户端字体都能显示该字符。

### 11.11 标准对齐原则

项目采用“参考标准的结构，不强求完整标准认证”的策略：

- ISO 24613-1:2024（LMF Core）作为词条、读音、词义和词形分层的主要参考。
- ISO 24613-2:2020（MRD）作为机器可读词典和导入模型的参考。
- ISO 24613-6:2024 作为词法、句法和语义关系的参考。
- ISO 639 用于语言代码。
- ISO 15924 用于文字脚本代码。
- `ja-JP` 作为当前发音/TTS 的 BCP 47 locale；它不替代语言代码和脚本代码。
- ISO 1951 主要用于词典条目的呈现原则，不直接决定数据库表结构。

## 12. 第一阶段完成标准

第一阶段可交付版本至少应满足：

- 管理员可以创建和管理账户。
- 用户可以创建单词本和个人学习条目。
- 用户可以引用系统词典，也可以创建待审核的用户词条。
- 系统能按固定书写形式执行词条去重，已存在时默认跳过且不覆盖。
- 词条支持多读音、多词义及主要项和展示顺序配置。
- 听觉测试隐藏答案，自动播放主要读音，支持重播和 `× / △ / ○` 评分。
- 例句音频不自动播放，点击哪个播放哪个。
- 每个用户拥有独立的 FSRS/DSR 进度和复习历史。
- `× / △` 能进入耳词池，多读音轮播不拆分状态。
- 音频能独立版本化并保存到 R2。
- 第一版能够离线学习，个人数据能重试同步，JSON导出暂缓开放；当前进度按实际答题时间最后的提交确定。
- 支持不设每日配额的分组穿插重试、到期优先、额外训练更新 FSRS、个人覆盖和范围进度重置。
- 词条所选类型全部完成后自动上传，失败保留待同步记录，并提供“上传今日学习进度”手动补传。
- 系统词典、用户贡献词条和个人学习状态的权限边界清晰。
