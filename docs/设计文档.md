# Language Lean 设计文档

> 文档状态：第一版功能与数据设计基线
> 当前阶段：日语 Web 版 MVP 项目骨架准备
> 更新日期：2026-09-12

## 1. 设计目标

本设计文档把项目概要中的需求转换为可实现的功能边界、领域边界、数据模型和核心流程。当前只设计第一版已有功能，不提前实现原生 App、复杂统计或 AI Agent 系统。

核心原则：

1. 系统词典负责提供内容，用户学习域负责保存个人学习状态。
2. 基准词条以固定书写形式为身份；一个词条可以有多个读音和多个词义。
3. FSRS/DSR 状态只属于一个用户的一个学习条目。
4. 个人词条与公开基准词条是不同实体；审核通过且公开后才能将内容录入基准词典，普通用户不能直接修改基准词典。
5. 内容和学习状态都使用稳定 ID、版本和迁移关系，不能依赖可变文字作为外键。
6. Web 存储、音频存储和复习算法通过接口隔离，不能互相污染核心模型。

~~~text

       ├── 系统词典（SYSTEM）
       │       ├── 基准词条
       │       ├── 读音
       │       ├── 词义
       │       ├── 例句
       │       └── 词汇关系
       │
       ├── 用户贡献词典（COMMUNITY）
       │       └── 创建者、审核、版本、来源
       │
       ├── 个人学习域
       │       ├── 单词本
       │       ├── 学习条目
       │       ├── FSRS/DSR 状态
       │       ├── 复习历史
       │       └── 耳词状态
       │
       ├── 音频域
       │       ├── 生成任务
       │       ├── 音频资产
       │       └── 音频版本
       │

~~~

系统词典表不保存用户复习状态。个人学习条目引用公开词条或个人词条，并允许保存个人释义、读音等覆盖内容。COMMUNITY 表示经审核公开的用户来源内容；私有词条和审核申请独立于公开基准词典，不占用公开词典的唯一键。

## 3. 词典内容模型

### 3.1 基准词条

~~~text
DictionaryEntry
  id
  language_id
  script_code
  written
  normalized_written_key
  origin_type: SYSTEM | USER_CONTRIBUTED
  lifecycle_status
  created_by_user_id
  current_revision_id
~~~

公开基准词典的唯一键为（不约束其他用户的个人词条）：

~~~text
language_id + script_code + normalized_written_key
~~~

读音和词义不参与基准词条的重复判定。相同书写形式只建立一个基准词条；不同书写形式不因读音或释义相同而合并。

每个词条具有全局唯一稳定 ID。公开与个人词条仍为独立实体；合并保留旧 ID 到 canonical_entry_id 的映射。全局 ID 不替代规范化写法去重，也不授予私人内容访问权限。公开收录或切换引用时，在用户范围内复用同一 learning_item_id、个人覆盖和单词本关联，避免第二份进度。若已有重复学习条目，归并关联、按事件 ID 去重历史，并按最新实际答题时间选择当前状态。

### 3.2 读音和词义

~~~text
DictionaryPronunciation
  entry_id
  reading
  pronunciation_locale
  is_primary
  display_order
  quality_status

DictionarySense
  entry_id
  display_order
  is_primary
  part_of_speech
  quality_status

DictionaryGloss
  sense_id
  language_id
  text
~~~

一个词条可以有多个读音和多个词义。主要项和展示顺序由后台配置，普通测试默认播放主要读音，耳词训练轮播可用读音。轮播不创建额外学习状态。

### 3.3 例句和词汇关系

~~~text
ExampleSentence
  id
  sentence_text
  pronunciation_text nullable
  language_id
  difficulty
  register
  region
  source_id
  license
  quality_status

SenseExample
  sense_id
  example_sentence_id
  relation_type: PRIMARY | SECONDARY
  display_order

LexicalRelation
  source_sense_id
  target_sense_id
  relation_type: SYNONYM | ANTONYM | RELATED | TRANSITIVE | AUTONYM
  source_id
  quality_status
~~~

近义词、反义词等关系绑定到词义，而不是无条件绑定整个词条。标准例句是词典内容；用户例句单独保存，不能修改标准例句。

### 3.4 词形和字符

活用或派生形式属于基准词条的派生数据，不改变基准词条身份：

~~~text
DictionaryForm
  entry_id
  form_type
  written
  reading
  grammatical_features
  generated
  rule_version
  quality_status
~~~

字符 Character 独立于词条，用于记录 Unicode 码点、部首、笔画、简繁关系以及日语音读/训读等字符属性。

## 4. 用户学习模型

### 4.1 个人学习条目

~~~text
UserLearningItem
  id
  user_id
  dictionary_entry_id nullable
  personal_custom_entry_id nullable
  manual_ear_focus
  created_at
  updated_at
~~~

dictionary_entry_id 和 personal_custom_entry_id 必须有且只有一个。前者引用公开基准词条，后者引用用户自己的个人词条（含不完整、完整和待审核内容）。个人词条可以关联来源基准词条，但仍是独立实体；学习条目不因个人覆盖而复制出另一份共享进度。

PersonalEntryOverride 按学习条目保存个人释义、读音及其他学习内容的覆盖；展示和训练使用个人有效内容，未覆盖部分引用基准内容。个人修改和删除不改变公开词典。具体覆盖字段及公开内容更新后的合并展示规则在接口设计时细化。

同一用户对同一个词典条目只保留一个学习条目。单词本使用关联表：

~~~text
WordbookLearningItem
  wordbook_id
  learning_item_id
~~~

这样同一个词加入多个单词本时复用同一份进度。单词本用于分类、选择复习范围和重置范围。

用户删除个人条目时彻底删除其个人内容、进度和历史，重新加入从零开始；公开基准词条不受影响。从 A 单词本移除仍被 B 引用的词，只删除 A 的关联，B 的共享进度保持不变；最后一个单词本移除时彻底删除对应个人学习条目与进度。

重置功能完整清除所选范围内全部学习进度信息，包括 FSRS 状态、复习计数、复习历史、自动耳词状态、手动耳词重点及耳词历史，恢复为未学习的初始状态；词条内容、个人内容覆盖和单词本关联保留。重置某个单词本时，重置其中包含的每个词的共享学习条目，即使其他单词本也引用该词，其进度和手动重点同样归零；不影响未包含在所选范围内的词。对应旧草稿和待提交进度失效，切换 progress_epoch 防止旧设备恢复被清除的状态。

### 4.2 FSRS/DSR 状态

FSRS 状态完全属于 UserLearningItem，不写入任何词典表：

~~~text
fsrs_algorithm
fsrs_algorithm_version
fsrs_state
last_reviewed_at
next_review_at
review_count
lapse_count
~~~

第一版评分映射为：

~~~text
× → Again
△ → Hard
○ → Good
~~~

暂不提供 Easy 按钮。目标保留率、初始学习步骤和具体 FSRS 版本通过配置确定。

到期词优先于新词。不设置每日数量或用户配额，选定范围内有多少待复习词就提供多少。每组最多 10 词只是分组大小，不限制每日总量。未到期词允许额外训练，每次完整训练也更新同一份 FSRS 状态。

第一版只有听音回忆自评，但从第一版开始采用可扩展的题型协议和复习轮次模型。未来一次词条复习可以选择多个复习类型；只有该轮所选类型全部完成，才计为一次完成的复习并更新一份 FSRS 状态。任意类型未完成时只保存本地草稿，不计入已完成复习、不更新正式 FSRS，也不提交完成事件。各类型分别评 × / △ / ○，取最差评分作为整轮最终评分（× 优先于 △，△ 优先于 ○），仅调用一次 FSRS 更新；保存逐项评分与最终评分以便追踪。

“看单词拼写假名”“听音选假名”“听音选单词”仅为未来题型示例，不纳入第一版，也不限定后续只有这三种。第一版不实现多题型页面或判题逻辑；上述规则作为后续扩展约定。

### 4.3 复习历史

~~~text
ReviewEvent
  id
  learning_item_id
  user_id
  training_mode: NORMAL | EAR_WORD
  presented_pronunciation_id nullable
  content_revision_id nullable
  rating
  replay_count
  response_ms nullable
  was_overdue
  reviewed_at
  fsrs_state_before
  fsrs_state_after
  algorithm_version
  base_version
  submission_version
  server_received_at
~~~

presented_pronunciation_id 只记录本次实际播放内容，不作为学习状态主键。多读音仍只更新同一份 FSRS 状态。

复习事件使用系统内部稳定的 user_id 关联同一用户的长期进度；对外导出或分析时不携带邮箱、用户名等直接身份信息。user_id 与真实身份的映射只由账户系统控制。当前不建设 AI Agent 训练管线。事件在正常复习期间追加保存；用户明确删除条目、重置进度或注销时按对应范围清除，不能以历史保留为由恢复已删除的进度。

耳词池可以使用 UserLearningItem 的当前状态和手动标记，并额外保存状态变更历史：

~~~text
EarWordEvent
  learning_item_id
  event_type: AUTO_ENTER | MANUAL_ENTER | MANUAL_EXIT | DEPRECATED
  reason
  created_at
~~~

### 4.4 题型扩展契约（第一版即采用）

扩展性属于当前设计与编码要求；第一版只启用 `LISTEN_RECALL`（听音回忆自评），不提前实现未来题型页面。单题型同样走轮次、结果聚合、本地持久化和上传流程，不另建一条无法复用的提交路径。

职责分为三层：

- 题型适配器：准备题面、声明所需资源、呈现交互并产生该题型的完成结果，不直接更新 FSRS 或调用进度上传。
- 复习轮次协调器：固定本轮必做题型清单，保存草稿，检查全部完成，汇总最差评分并创建一个完成事件。
- 复习与同步服务：以幂等事件更新一份 FSRS，持久保存本地待同步记录并自动/手动上传；不依赖题型页面组件。

题型适配器的最小契约：

~~~text
ReviewTypeDefinition
  type_id                       // 稳定代码，第一版 LISTEN_RECALL
  contract_version
  supported_languages
  required_resources            // 例如词条内容、读音音频
  supports_offline

ReviewTypeAdapter
  prepare(context) -> prepared_question
  restore(draft) -> interaction_state
  complete(answer_or_self_rating) -> ReviewTypeResult
~~~

采用题型注册表按 type_id 查找适配器。后台按当前语言返回启用题型及协议版本，前端只提供后台启用且本客户端已实现的题型；遇到未知题型或不兼容协议明确提示，不静默当成听音回忆，也不能跳过它将整轮标记完成。第一版只注册听音回忆适配器。

~~~text
ReviewAttempt
  attempt_id
  learning_item_id
  training_mode                 // NORMAL | EAR_WORD，与题型是不同维度
  base_version
  content_revision_id
  required_review_types[]       // type_id + contract_version，本轮开始时快照
  type_results[]
  training_batch_id nullable
  training_group_id nullable
  status                        // IN_PROGRESS | COMPLETED
  started_at
  completed_at nullable
  final_rating nullable
  submission_version nullable

ReviewTypeResult
  type_id
  contract_version
  status
  rating nullable               // AGAIN | HARD | GOOD
  completed_at nullable
  payload_schema_version
  payload                       // 该题型自己的答案、播放等必要结果
  trials[]                      // 每次尝试的 ID、时间、评分及必要结果，失败也保留
  passed_at nullable            // 重试模式下首次得到 HARD 或 GOOD 的时间
~~~

整轮未完成时只有草稿；所有 required_review_types 均通过后才设置 completed_at、final_rating 和 submission_version。第一版只有一种题型但可以有多次尝试，最终评分取全部尝试的最差值；未来再跨题型取最差值。一次轮次只产生一个 ReviewEvent，不为每次尝试或每个题型重复更新 FSRS。

第一版单题型及未来多题型的重试模式中，“通过”与“评分”分别判断：该词该题型出现 HARD 或 GOOD 后才通过，但题型评分取全部尝试中的最差值，不能用最后一次通过的评分覆盖失败。词条最终评分再取全部题型的最差值。因此 A 曾 AGAIN、重试 GOOD，B/C 都 GOOD 时，整轮完成但最终评分仍为 AGAIN，更新 FSRS 并按 AGAIN 更新耳词状态。

上述字段属于第一版 API、IndexedDB 草稿和待同步事件的共同契约。ReviewEvent 保存 attempt_id、必做题型快照、逐项结果、最终评分和协议版本，服务端校验完成性与评分一致性，不能只相信客户端的 COMPLETED 标记。同步幂等性绑定整轮事件，而不是每种题型。

新增题型时增加定义、适配器、资源准备和结果校验，复用轮次协调器、FSRS 和上传服务。题型专属 payload 必须有明确版本和校验结构，不能依赖无约束 JSON 随意扩展。具体物理表/JSON 字段选择在建表时确定，但不得省略这些领域边界。

### 4.5 分组与穿插重试（第一版即实现）

第一版听音回忆即采用每组最多 10 词和穿插重试：Again 不算通过，重试至 Hard/Good，失败尝试仍参与最终最差评分。第一版每组只有一个题型阶段，未来增加多个阶段时复用同一调度流程。

- 本次选定的复习词条分组，每组最多 10 个词条，按既有到期优先队列顺序分组。例如 23 个词可分为 10、10、3。
- 按“小组 → 题型 → 词条”推进。选择 A/B/C 时，先完成第一组全部词的 A，再完成这一组全部词的 B、C，最后进入下一组；不能把同一个词的 A/B/C 紧邻做完。
- 在当前题型阶段，某词选 AGAIN 不算通过，自动追加到本阶段剩余队列队尾；直到选择 HARD 或 GOOD 才标记该词此题型通过。仅剩该词时，它自动成为下一题，不要求点击“再次测试”。
- 只有本组所有词都通过当前题型，才推进下一个题型。每次失败和重试都持久保存在本地草稿中，恢复训练不得丢掉失败评分或重试队列。
- 某词完成全部所选题型后立即生成该词的一个完成事件并尝试上传，无须等待本组其他词完成。中间尝试不独立更新 FSRS、不计为多次完整复习，也不作为完成事件上传。
- 每词最终评分取所有题型、所有尝试中的最差值，最终完成时间用于实际答题时间排序；完整保留每次尝试时间以区分过程与完成。

第一版采用的批次状态（当前只有一个题型阶段）：

~~~text
TrainingBatch
  batch_id
  ordered_review_types[]
  groups[]                      // 每组最多 10 个不同学习条目
  current_group_index

TrainingGroup
  group_id
  learning_item_ids[]
  current_type_index
  pending_queue[]
  retry_queue[]
  passed_learning_item_ids[]    // 当前题型已通过的词
~~~

批次/分组调度器负责推进阶段与安排穿插重试，题型适配器仍只负责当前题的交互和结果；词条轮次协调器聚合逐次尝试并判断词条是否全部完成。不能将队列调度散落到各题型页面中，也不能把分组作为 FSRS 状态或上传的单位。

不设置固定间隔词数，始终按剩余队列队尾重试。每次用户点击判定后立即持久保存该次尝试、最差评分及更新后的队列，再进入下一题；仅剩一个词时也重新隐藏答案并正常呈现该题，不能自动判为通过。中途退出后恢复本地批次、阶段及队列。

## 5. 用户贡献词条

### 5.1 内容与权限

个人词条、贡献审核申请和公开基准词条独立存储。个人词条可以采用与基准词条相同的内容结构，但唯一性限定在所属用户范围内。贡献申请保存提交时的内容快照，审核人员只处理被提交的内容，不自动获得其他个人学习内容。审核申请至少保存：

~~~text
submitted_by_user_id
personal_entry_id nullable
target_dictionary_entry_id nullable
base_revision_id nullable
submitted_content_snapshot
moderation_status: PENDING_REVIEW | APPROVED | REJECTED
publish_requested
source
license
~~~

创建者在审核期间继续使用自己的个人内容；审核通过且公开后才创建或更新公开基准词条。同写法的公开条目已存在时提交其修订，不重复创建公开条目。后续修改个人内容不会自动修改公开词典，删除个人词条也不删除已录入的公开条目。用户标签、笔记、学习记录和未提交的私人例句不随审核公开。

### 5.2 版本与合并

~~~text
DictionaryEntryRevision
  entry_id
  revision_number
  parent_revision_id
  content_snapshot
  content_hash
  created_by
  change_reason
  created_at

DictionaryMigration
  old_entry_id
  new_entry_id
  migration_type: MERGE | SPLIT | REPLACE | PROMOTE | DEPRECATE
  reason
  created_at
~~~

公开词条保存线性的已发布历史版本，快照必须能恢复读音、词义、例句关联等完整内容。待审修改单独保存，审核前查询仍返回旧公开版，审核通过并发布后切换 current_revision_id。并发待审申请发布时应检查基准版本，避免覆盖其他已审核修改。

回退或纠错通过追加新的已发布版本实现，引用所恢复的历史内容，不覆写历史记录。公开词条被封禁或删除后，已有引用显示“已封禁”或“已删除”，不再当作正常可用公开词条展示。公开端保留必要的 ID、状态和版本用于引用与纠错；这不阻止用户彻底删除自己的个人条目。恢复发布权限和封禁后私人覆盖内容的展示细节待确认。

### 5.3 未解析词条

个人词条可以先只有写法，也可以具有完整内容；它不是临时占用公开基准词条的记录：

~~~text
PersonalCustomEntry
  user_id
  raw_written
  reading nullable
  meaning nullable
  language_id
  script_code
  normalized_written_key
  source_dictionary_entry_id nullable
  status: INCOMPLETE | COMPLETE
~~~

没有读音时不能生成 TTS，但不阻止用户先保存和整理。提交审核使用独立申请；发布后个人实体与公开实体保持分离。个人去重使用 user_id + language_id + script_code + normalized_written_key。

## 6. 音频模型

音频文件存在但读音错误时：用户可修改自己的发音内容并重新生成个人音频；公共音频提供问题反馈，由管理员修正内容并重新生成，普通用户不直接改公共音频。此流程与缺失文件的自动补生成区分，重新生成仍沿用独立版本与锁内检查。

~~~text
AudioAsset
  owner_type: DICTIONARY | COMMUNITY | PERSONAL
  owner_id
  audio_kind: WORD | EXAMPLE
  pronunciation_id nullable
  example_sentence_id nullable
  current_version_id

AudioVersion
  audio_asset_id
  version_number
  provider
  model
  voice
  text_hash
  file_hash
  object_key
  generation_status
  created_at
~~~

每个词条读音或例句拥有独立音频版本。新版本上传 R2 成功后才切换 current_version_id，失败时旧版本继续可用。

保存可生成音频的内容时自动触发 TTS；联网打开单词详情发现缺少音频时再次触发。个人音频自动生成由后台管理页面配置，当前默认开启。

用户点击词条发音或例句音频时也必须检查对应音频是否已生成且可用，不能只依赖保存或打开详情时的检查。没有生成成功的可用音频（包括此前生成失败）时，联网条件下调用同一补生成流程；生成成功后播放所点击的音频。已有可用音频直接播放，不因每次点击重复生成；已有生成任务则复用任务并等待结果。

生成前先检查所点击对象是否填写发音：词条发音未填写，或例句发音未填写，都跳过 TTS 生成，不以原始写法/例句正文自动代替缺失的发音输入。该前置条件统一适用于保存、详情补生成和点击播放触发，避免反复创建必然失败的任务。页面提示需要补充发音；用户仍可以保存、查看和整理内容。例句模型需预留可选的发音文本字段，具体存储形式在接口/建表时细化。

点击触发仍遵守个人 TTS 后台配置及内容权限；关闭个人生成时不绕过配置。断网时优先播放缓存，缺失缓存则提示联网后重试，不能在离线状态宣称已重新生成。

生成流程为：检查有效音频 → 获取同一音频生成键的排他锁 → 再次检查音频及已有任务 → 仅在仍缺失时生成 → 上传 R2 → 原子切换版本 → 释放锁。生成键包含内容哈希、语言、声音和模型，以及必要的公开/个人权限范围。单例服务对象本身不提供并发去重；锁和任务唯一约束需要覆盖同一部署中的全部请求与工作进程。异常时释放锁并允许重试，避免任务永久卡住。

离线学习只能播放已缓存音频，断网时不能调用服务端 TTS。需要预先缓存学习内容和对应音频；缺失或生成失败时显示明确状态并允许联网补齐，不静默跳过、记分或推进题目。离线准备按用户选定的学习范围下载，见第 9 节。

## 7. 核心流程

### 7.1 系统词典导入

~~~text
第一版开源词典来源（具体数据集待选定；后续支持追加导入和管理员手工录入）
→ 导入暂存区
→ UTF-8 和格式校验
→ 书写规范化
→ 按 language + script + written 去重
→ 冲突检查
→ 管理员审核
→ 发布词条版本
→ 构建搜索、分词、变形和音频派生数据
~~~

已存在的基准词条不重复创建，不覆盖原有内容。新的读音、词义和例句作为同一条目下的待审核补充。

### 7.2 用户创建或导入

~~~text
用户输入写法
→ 查询系统词条
→ 查询已发布用户贡献词条
→ 找到则引用已有条目
→ 未找到则创建个人词条；找到后也可保存自己的覆盖内容
→ 创建 UserLearningItem
→ 加入一个或多个单词本
~~~

CSV 导入在同一用户范围内按已解析的词典条目 ID，或未解析内容的规范化书写形式去重；已存在时默认跳过，不覆盖释义、标签、音频和 FSRS 状态。

### 7.3 听觉训练

~~~text
取得 FSRS 已到期学习队列（新词按初始调度进入；未到期词仅在额外训练入口选择）
→ 选择主要读音或轮播读音
→ 隐藏答案并播放单词音频
→ 用户可以重播
→ 显示写法、全部读音、主要词义和例句
→ 完成该轮所选复习类型（任意一项未完成则保留草稿）
→ 全部题型通过后，取所有尝试的最差 × / △ / ○ 评分
→ 在同一本地事务中保存完成事件、FSRS、耳词状态和待上传记录
→ 立即尝试上传该词条的完成事件，失败则保留待同步记录
→ 进入下一题
~~~

例句不自动播放；用户点击哪个音频就播放哪个音频。

该轮最终完成时间作为实际答题时间用于同步排序。一个完成事件具有独立幂等 ID，自动上传、网络重试和手动补传重复发送同一事件不重复计分。第一版即保存 required_review_types 快照和逐项完成结果，当前清单只有 LISTEN_RECALL。草稿在本地持久保存；跨设备草稿同步及未来多题型中途继续的交互细节留待扩展模块确定。

### 7.4 搜索

~~~text
输入
→ Unicode 和语言规范化
→ 精确系统词条
→ 精确用户贡献词条
→ 精确个人词条
→ 变形还原、读音和文字变体
→ 模糊匹配
→ 动态 score 排序
~~~

来源优先级高于模糊匹配分数。个人词条只对创建者可见。

## 8. API 模块

后端按业务边界组织 API，不把 TTS 或 Web 存储细节暴露给训练页面：

- auth：用户名或邮箱登录、当前用户、邮件初始密码/找回、登录态修改密码和管理员账号管理。
- languages：当前启用语言、脚本和功能入口。
- dictionary：查询、词条详情、读音、词义、例句和词汇关系。
- contributions：用户贡献词条创建、提交审核、审核和版本。
- wordbooks：单词本和学习条目关联。
- learning-items：个人学习条目、个人词条、个人覆盖、标签、删除与范围进度重置。
- reviews：到期队列、复习提交和历史。
- ear-words：耳词池查询、手动加入和取消。
- audio：生成任务、状态、版本和播放地址。
- sync：当前账户的增量同步和手动全量同步。
- backup：JSON 导出和后续恢复入口。

所有个人数据 API 必须以当前认证用户为范围；管理员审核接口单独授权。OpenAPI 文档是接口契约来源。

## 9. 本地缓存与同步

本地缓存分为三类：

~~~text
词典内容缓存：按词条和版本缓存
音频缓存：按 AudioVersion 独立缓存
个人数据缓存：学习状态、复习事件、单词本和标签
~~~

离线准备：第一版缓存应用页面及必要静态资源，支持已准备的用户断网关闭后重新打开。提供按选定学习范围下载内容和音频的入口，区分未准备、准备中、已准备、部分失败，逐项检查资源并允许重试；首次访问及未准备资源仍需联网。

没有发音的词保留在单词本，标记待补充发音，不进入听力队列、不计为已复习。有发音但缺少音频属于资源未准备，补齐后再训练。

同步原则：

- 默认当日复习队列依据 FSRS 的 next_review_at 与当前时间判断到期；未到期词不加入当日应复习清单，额外训练入口仍保留。新词使用初始调度状态确定是否可进入，不绕过调度条件自动把所有新词加入当日清单；具体初始学习步骤随 FSRS 参数确定。

- 当前词条页面按需同步相关内容。
- 手动同步作用于当前账户的全部个人数据。
- 第一版必须支持断网学习，本地先持久保存事件和更新后的进度，联网后可重试同步。
- 按词条完成立即自动上传，不等待整个学习队列结束。多类型训练必须全部完成后才生成并上传该词条的一次完成事件；部分完成仅保存本地草稿。
- 提供“上传今日学习进度”入口，补传今日已完成但尚未确认上传的事件；不得把未完成轮次当作完成上传。成功确认前不删除本地待同步事件，失败保留并允许重试。
- 今日入口是手动补传渠道，不替代自动上传、恢复联网重试或既有的全账户同步。跨日遗留待同步事件仍保留并由常规重试/全量同步处理；今日日期时区及是否在该入口同时补传历史积压待细化。
- 每次提交记录幂等事件 ID、基准版本、本次版本、答题时间和服务端接收时间。正常使用期间事件追加保存；多设备冲突的当前进度按最后一次提交覆盖，不叠加冲突分支的 FSRS 状态。
- 最后提交按实际答题时间排序，不按上传或服务端接收时间；昨天的离线记录今天上传，不覆盖今天已经完成的较新进度。用户倾向用时间戳比较版本；时间戳不能单独充当事件唯一 ID，同毫秒并发和设备时钟偏差的处理须在协议实现前确定。
- 词典版本更新不删除用户学习状态。
- 本地离线产生的个人事件需要具备幂等 ID。
- 学习条目保存 progress_epoch（重置代次），草稿和提交均携带该值。重置清除进度、历史和旧草稿并切换新代次；服务端先验证代次，再比较实际答题时间。旧代次事件不能恢复进度。删除保留最小同步标记，重新加入使用新的 learning_item_id；注销使旧会话和提交失效。标记不保存已删除学习内容，清理周期在同步实现时细化。
- 离线期间无法立即获知远程封禁或删除；重新连接同步后应更新本地状态并显示对应提示。

### 9.1 多账号本地缓存与提交确认

缓存账号归属使用 account_key = 服务端实例标识 + 稳定 user_id，不使用可变邮箱、用户名或当前页面登录名。学习开始时固定 account_key，切换账号不能重写旧草稿/事件的归属。允许同一设备保留多个账户的本地数据；注销后以同名重新创建的账户有新 user_id，不可继承旧分区。

~~~text
CachedAccount       [account_key]                         // 账户显示信息、离线准备状态；不保存明文密码
LearningStateCache  [account_key, learning_item_id]       // progress_epoch、FSRS、耳词状态、服务端版本
TrainingDraft       [account_key, batch_id]               // 分组、队列、阶段及词条轮次/逐次判定
PendingReview       [account_key, event_id]               // attempt_id、learning_item_id、progress_epoch
                                                         // base_version、submission_version、完整结果、同步状态
SyncCursor          [account_key]                        // 当前账户同步位置
PersonalAudioCache  [account_key, audio_version_id]       // 私人音频按账号隔离
PublicContentCache  [server_instance_id, entity_id, version] // 仅已发布公共内容允许共享
~~~

登录过期时，已有离线准备的账号可以继续在自己的缓存分区学习。恢复联网后要求登录对应账户，上传器仅发送与当前认证 user_id 和服务端实例匹配的事件；服务端验证学习条目归属，不信任请求体自报 user_id。登录 B 时不上传 A 的数据；A 的未同步记录保留并提示切回 A。所有查询、清理和后台重试均须使用账号分区。

每次判定先写本地事务；存储失败时提示且不推进队列。词条完成时原子更新学习状态并写 PendingReview。只有收到服务端逐事件的持久接收确认后，才删除该事件的待上传副本及对应已完成轮次草稿；不能在发出请求、超时或仅获批量请求成功时就清空缓存。部分成功只清理已确认事件；响应丢失用同一事件 ID 重试。

“提交后删除本地缓存”指清理已确认提交的过程记录与待提交副本，不删除离线学习所需词条、音频和当前状态。进行中的其他词草稿继续保留；批次尚未结束时保留最小完成标记，避免恢复队列又重复练已提交词。较旧事件被持久接收但不改变当前进度时也应明确返回处理结果；重置失效等拒绝结果单独提示，不伪装为提交成功。

## 10. 权限和审计

- SYSTEM 词典只能由管理员导入、审核和发布。
- 用户修改自己的内容；公开词典变更通过独立申请和管理员审核发布。
- USER 只能读取已发布公共内容和自己的个人内容。
- 公开词条的创建者、来源和许可证可以展示；个人笔记和学习记录不可公开。
- 注销账户彻底清除该用户个人内容和学习数据，撤销会话；相同邮箱或用户名再次创建账户时生成新的 user_id，不关联旧数据。已审核公开的基准词条独立保留，历史来源署名、审核记录及备份清理方式需要在删除策略中细化。
- 词典审核、版本发布、迁移、封禁和管理员操作必须保留审计记录。

账户创建时用户名和邮箱都必填，两者均可登录；第一版仍关闭公开注册，由管理员创建。初始密码通过邮件发送，找回密码也使用邮件渠道。登录后修改密码需填写原密码、新密码、重复新密码。找回邮件使用临时密码还是重置链接、临时凭据有效期和首次登录换密规则待确认；不通过邮件发送现有密码。

## 11. 标准对齐

项目参考以下标准的分层思想，但不强求完整标准认证：

- [ISO 24613-1:2024 LMF Core](https://www.iso.org/standard/82014.html)：词典资源核心模型。
- [ISO 24613-2:2020 MRD](https://www.iso.org/standard/75407.html)：机器可读词典模型。
- [ISO 24613-6:2024](https://committee.iso.org/cms/live/live/en/sites/isoorg/contents/data/standard/08/31/83180.html)：词法、句法和语义关系。
- [ISO 639](https://www.iso.org/iso-639-language-code)：语言代码。
- [ISO 15924:2022](https://www.iso.org/standard/81905.html)：文字脚本代码。
- [ISO 1951:2026](https://www.iso.org/standard/84863.html)：词典条目呈现原则。

发音和 TTS 使用独立的 BCP 47 locale；当前使用 ja-JP。上述标准只约束参考结构和编码，不改变项目确定的“固定书写形式作为基准词条”规则，也不决定数据库表结构。

## 13. 数据库逻辑表清单

以下为 PostgreSQL 的逻辑表分组。实际建表时使用 Flyway 迁移，并为所有业务实体使用稳定 ID。

### 13.1 账户和配置

~~~text
user_account
user_role
language_config
language_feature
system_config
audit_log
~~~

user_account 保存登录和状态；词典内容不保存用户学习状态。language_config 保存语言、脚本、发音 locale、释义语言和 TTS 配置；前端通过接口读取启用语言及功能入口。

### 13.2 词典和来源

~~~text
dictionary_source
dictionary_import_batch
dictionary_import_row
dictionary_entry
dictionary_entry_revision
dictionary_contribution_submission
dictionary_pronunciation
dictionary_sense
dictionary_gloss
example_sentence
sense_example
dictionary_form
lexical_relation
entry_component
dictionary_migration
character
~~~

dictionary_entry 只保存公开基准词条，其唯一身份是 language + script + normalized_written_key；origin_type 区分开源导入、管理员维护或已审核用户贡献的来源。个人内容存入个人域，待审内容存入 dictionary_contribution_submission；它们不占用公开词条唯一键。读音、词义、例句、词形和关系必须可按已发布版本还原。

### 13.3 个人学习数据

~~~text

personal_entry_override
user_learning_item
wordbook_learning_item
user_learning_tag
user_note

~~~

user_learning_item 必须且只能引用 dictionary_entry 或 personal_custom_entry；同一用户对同一词典条目只能存在一个学习条目。wordbook_learning_item 允许一个学习条目关联多个单词本。

### 13.4 音频、同步和备份

~~~text
audio_asset
audio_version
audio_generation_job
sync_change
sync_cursor
backup_job
backup_object
~~~

audio_version 独立记录服务商、模型、声音、文本哈希、文件哈希、R2 对象键和生成状态。同步变更使用幂等事件 ID；备份表只记录任务和对象元数据，不在数据库中保存 MP3。

### 13.5 关键约束

- dictionary_entry 对非归档条目使用 language、script 和 normalized_written_key 的唯一约束。
- dictionary_pronunciation 在同一词条内按规范化读音去重，并限制最多一个主要读音。
- dictionary_sense 和 sense_example 使用 display_order；每个词条和例句的主要项由业务规则校验。
- user_learning_item 对 user_id 和 dictionary_entry_id 建唯一约束；个人词条按 user_id、language_id、script_code 和 normalized_written_key 去重。
- review_event 正常复习时只追加；当前 FSRS 状态按最后提交规则更新。删除、重置和注销按用户要求清除对应历史。
- 公开词条保留版本及封禁/删除状态；个人词条删除不影响公开词条。
- 词典和用户个人数据的删除、迁移、审核和发布必须写入 audit_log。
