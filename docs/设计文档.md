# Language Lean 设计文档

> 文档状态：第一版功能与数据设计基线
> 当前阶段：日语 Web 版 MVP 项目骨架准备
> 更新日期：2026-09-12

## 1. 设计目标

本设计文档把项目概要中的需求转换为可实现的功能边界、领域边界、数据模型和核心流程。当前只设计第一版已有功能，不提前实现原生 App、复杂统计或 AI Agent 系统。

核心原则：

1. 系统词典负责提供内容，用户学习域负责保存个人学习状态。
2. 基准词条以固定书写形式为身份；一个词条可以有多个读音和多个词义。
3. FSRS/DSR 状态只属于一个用户的一个学习条目。
4. 系统词典只读；用户贡献词条经过审核后共享。
5. 内容和学习状态都使用稳定 ID、版本和迁移关系，不能依赖可变文字作为外键。
6. Web 存储、音频存储和复习算法通过接口隔离，不能互相污染核心模型。

## 2. 领域边界

~~~text
账户与权限
       │
       ├── 系统词典（SYSTEM）
       │       ├── 基准词条
       │       ├── 读音
       │       ├── 词义
       │       ├── 例句
       │       └── 词汇关系
       │
       ├── 用户贡献词典（COMMUNITY）
       │       └── 创建者、审核、版本、来源
       │
       ├── 个人学习域
       │       ├── 单词本
       │       ├── 学习条目
       │       ├── FSRS/DSR 状态
       │       ├── 复习历史
       │       └── 耳词状态
       │
       ├── 音频域
       │       ├── 生成任务
       │       ├── 音频资产
       │       └── 音频版本
       │
       └── 同步与备份
~~~

系统词典表不保存用户复习状态；用户学习表只保存对词典内容的引用。用户贡献词条需要保存创建者用于审核和溯源，但不保存任何用户学习进度。

## 3. 词典内容模型

### 3.1 基准词条

~~~text
DictionaryEntry
  id
  language_id
  script_code
  written
  normalized_written_key
  origin_type: SYSTEM | USER_CONTRIBUTED
  lifecycle_status
  created_by_user_id
  current_revision_id
~~~

基准唯一键为：

~~~text
language_id + script_code + normalized_written_key
~~~

读音和词义不参与基准词条的重复判定。相同书写形式只建立一个基准词条；不同书写形式不因读音或释义相同而合并。

### 3.2 读音和词义

~~~text
DictionaryPronunciation
  entry_id
  reading
  pronunciation_locale
  is_primary
  display_order
  quality_status

DictionarySense
  entry_id
  display_order
  is_primary
  part_of_speech
  quality_status

DictionaryGloss
  sense_id
  language_id
  text
~~~

一个词条可以有多个读音和多个词义。主要项和展示顺序由后台配置，普通测试默认播放主要读音，耳词训练轮播可用读音。轮播不创建额外学习状态。

### 3.3 例句和词汇关系

~~~text
ExampleSentence
  id
  sentence_text
  language_id
  difficulty
  register
  region
  source_id
  license
  quality_status

SenseExample
  sense_id
  example_sentence_id
  relation_type: PRIMARY | SECONDARY
  display_order

LexicalRelation
  source_sense_id
  target_sense_id
  relation_type: SYNONYM | ANTONYM | RELATED | TRANSITIVE | AUTONYM
  source_id
  quality_status
~~~

近义词、反义词等关系绑定到词义，而不是无条件绑定整个词条。标准例句是词典内容；用户例句单独保存，不能修改标准例句。

### 3.4 词形和字符

活用或派生形式属于基准词条的派生数据，不改变基准词条身份：

~~~text
DictionaryForm
  entry_id
  form_type
  written
  reading
  grammatical_features
  generated
  rule_version
  quality_status
~~~

字符 Character 独立于词条，用于记录 Unicode 码点、部首、笔画、简繁关系以及日语音读/训读等字符属性。

## 4. 用户学习模型

### 4.1 个人学习条目

~~~text
UserLearningItem
  id
  user_id
  dictionary_entry_id nullable
  personal_custom_entry_id nullable
  manual_ear_focus
  created_at
  updated_at
~~~

dictionary_entry_id 和 personal_custom_entry_id 必须有且只有一个。一个用户可以引用系统词典条目、已发布的用户贡献词条，或自己创建的待审核词条；暂时不存在于词典的内容使用 personal_custom_entry。

同一用户对同一个词典条目只保留一个学习条目。单词本使用关联表：

~~~text
WordbookLearningItem
  wordbook_id
  learning_item_id
~~~

这样同一个词加入多个单词本时复用同一份进度。

### 4.2 FSRS/DSR 状态

FSRS 状态完全属于 UserLearningItem，不写入任何词典表：

~~~text
fsrs_algorithm
fsrs_algorithm_version
fsrs_state
last_reviewed_at
next_review_at
review_count
lapse_count
~~~

第一版评分映射为：

~~~text
× → Again
△ → Hard
○ → Good
~~~

暂不提供 Easy 按钮。目标保留率、初始学习步骤和具体 FSRS 版本通过配置确定。

### 4.3 复习历史

~~~text
ReviewEvent
  id
  learning_item_id
  user_id
  training_mode: NORMAL | EAR_WORD
  presented_pronunciation_id nullable
  content_revision_id nullable
  rating
  replay_count
  response_ms nullable
  was_overdue
  reviewed_at
  fsrs_state_before
  fsrs_state_after
  algorithm_version
~~~

presented_pronunciation_id 只记录本次实际播放内容，不作为学习状态主键。多读音仍只更新同一份 FSRS 状态。

复习事件使用系统内部稳定的 user_id 关联同一用户的长期进度；对外导出或分析时不携带邮箱、用户名等直接身份信息。user_id 与真实身份的映射只由账户系统控制。当前不建设 AI Agent 训练管线。

耳词池可以使用 UserLearningItem 的当前状态和手动标记，并额外保存状态变更历史：

~~~text
EarWordEvent
  learning_item_id
  event_type: AUTO_ENTER | MANUAL_ENTER | MANUAL_EXIT | DEPRECATED
  reason
  created_at
~~~

## 5. 用户贡献词条

### 5.1 内容与权限

用户贡献词条使用与系统词典相同的内容结构，但额外保存：

~~~text
created_by_user_id
origin_type: USER_CONTRIBUTED
visibility: PRIVATE | PUBLIC
moderation_status: PENDING_REVIEW | ACTIVE | DEPRECATED | BLOCKED
source
license
current_revision_id
~~~

创建者在审核期间可以使用自己的词条；只有审核通过的 ACTIVE 词条才能被其他用户搜索和引用。用户标签、笔记、学习记录和私人例句不随词条公开。

### 5.2 版本与合并

~~~text
DictionaryEntryRevision
  entry_id
  revision_number
  content_hash
  created_by
  change_reason
  created_at

DictionaryMigration
  old_entry_id
  new_entry_id
  migration_type: MERGE | SPLIT | REPLACE | PROMOTE | DEPRECATE
  reason
  created_at
~~~

已经被其他用户引用的词条不能硬删除。系统词典后来收录相同书写形式时，应通过 PROMOTE 或 MERGE 迁移，保留旧 ID、版本和用户学习进度。

### 5.3 未解析词条

用户可以先创建只有写法的个人未解析词条：

~~~text
PersonalCustomEntry
  user_id
  raw_written
  reading nullable
  meaning nullable
  language_id
  status: INCOMPLETE | READY_FOR_REVIEW | CONVERTED
~~~

没有读音时不能生成 TTS，但不阻止用户先保存和整理。审核通过后转换为用户贡献词条。

## 6. 音频模型

~~~text
AudioAsset
  owner_type: DICTIONARY | COMMUNITY | PERSONAL
  owner_id
  audio_kind: WORD | EXAMPLE
  pronunciation_id nullable
  example_sentence_id nullable
  current_version_id

AudioVersion
  audio_asset_id
  version_number
  provider
  model
  voice
  text_hash
  file_hash
  object_key
  generation_status
  created_at
~~~

每个词条读音或例句拥有独立音频版本。新版本上传 R2 成功后才切换 current_version_id，失败时旧版本继续可用。

## 7. 核心流程

### 7.1 系统词典导入

~~~text
原始来源
→ 导入暂存区
→ UTF-8 和格式校验
→ 书写规范化
→ 按 language + script + written 去重
→ 冲突检查
→ 管理员审核
→ 发布词条版本
→ 构建搜索、分词、变形和音频派生数据
~~~

已存在的基准词条不重复创建，不覆盖原有内容。新的读音、词义和例句作为同一条目下的待审核补充。

### 7.2 用户创建或导入

~~~text
用户输入写法
→ 查询系统词条
→ 查询已发布用户贡献词条
→ 找到则引用已有条目
→ 未找到则创建个人未解析项或用户贡献词条
→ 创建 UserLearningItem
→ 加入一个或多个单词本
~~~

CSV 导入在同一用户范围内按已解析的词典条目 ID，或未解析内容的规范化书写形式去重；已存在时默认跳过，不覆盖释义、标签、音频和 FSRS 状态。

### 7.3 听觉训练

~~~text
取得到期的 UserLearningItem
→ 选择主要读音或轮播读音
→ 隐藏答案并播放单词音频
→ 用户可以重播
→ 显示写法、全部读音、主要词义和例句
→ 用户选择 × / △ / ○
→ FSRS 更新同一个学习条目
→ × / △ 更新耳词状态
→ 进入下一题
~~~

例句不自动播放；用户点击哪个音频就播放哪个音频。

### 7.4 搜索

~~~text
输入
→ Unicode 和语言规范化
→ 精确系统词条
→ 精确用户贡献词条
→ 精确个人词条
→ 变形还原、读音和文字变体
→ 模糊匹配
→ 动态 score 排序
~~~

来源优先级高于模糊匹配分数。个人词条只对创建者可见。

## 8. API 模块

后端按业务边界组织 API，不把 TTS 或 Web 存储细节暴露给训练页面：

- auth：登录、当前用户和管理员账号管理。
- languages：当前启用语言、脚本和功能入口。
- dictionary：查询、词条详情、读音、词义、例句和词汇关系。
- contributions：用户贡献词条创建、提交审核、审核和版本。
- wordbooks：单词本和学习条目关联。
- learning-items：个人学习条目、个人未解析词条和标签。
- reviews：到期队列、复习提交和历史。
- ear-words：耳词池查询、手动加入和取消。
- audio：生成任务、状态、版本和播放地址。
- sync：当前账户的增量同步和手动全量同步。
- backup：JSON 导出和后续恢复入口。

所有个人数据 API 必须以当前认证用户为范围；管理员审核接口单独授权。OpenAPI 文档是接口契约来源。

## 9. 本地缓存与同步

本地缓存分为三类：

~~~text
词典内容缓存：按词条和版本缓存
音频缓存：按 AudioVersion 独立缓存
个人数据缓存：学习状态、复习事件、单词本和标签
~~~

同步原则：

- 当前词条页面按需同步相关内容。
- 手动同步作用于当前账户的全部个人数据。
- 个人复习事件采用追加方式同步，避免多设备覆盖历史。
- 词典版本更新不删除用户学习状态。
- 本地离线产生的个人事件需要具备幂等 ID。

## 10. 权限和审计

- SYSTEM 词典只能由管理员导入、审核和发布。
- COMMUNITY 词条的创建者可以提交修改，管理员负责审核。
- USER 只能读取已发布公共内容和自己的个人内容。
- 公开词条的创建者、来源和许可证可以展示；个人笔记和学习记录不可公开。
- 删除用户账号前，系统需要处理其贡献词条的归属、公开版本和学习引用。
- 词典审核、版本发布、迁移、封禁和管理员操作必须保留审计记录。

## 11. 标准对齐

项目参考以下标准的分层思想，但不强求完整标准认证：

- [ISO 24613-1:2024 LMF Core](https://www.iso.org/standard/82014.html)：词典资源核心模型。
- [ISO 24613-2:2020 MRD](https://www.iso.org/standard/75407.html)：机器可读词典模型。
- [ISO 24613-6:2024](https://committee.iso.org/cms/live/live/en/sites/isoorg/contents/data/standard/08/31/83180.html)：词法、句法和语义关系。
- [ISO 639](https://www.iso.org/iso-639-language-code)：语言代码。
- [ISO 15924:2022](https://www.iso.org/standard/81905.html)：文字脚本代码。
- [ISO 1951:2026](https://www.iso.org/standard/84863.html)：词典条目呈现原则。

发音和 TTS 使用独立的 BCP 47 locale；当前使用 ja-JP。上述标准只约束参考结构和编码，不改变项目确定的“固定书写形式作为基准词条”规则，也不决定数据库表结构。

## 12. 第一阶段功能清单

### 必须完成

- 管理员创建和管理账号。
- 日语语言配置从后台接口获取。
- 系统词典查询和词条详情。
- 用户贡献词条创建、待审核和发布。
- 个人单词本、学习条目和 CSV 导入。
- 按固定书写形式去重，已存在默认跳过且不覆盖。
- 多读音、多词义、主要项和展示顺序。
- 单词音频自动播放、手动重播。
- 例句音频点击播放，不自动播放。
- FSRS/DSR 用户独立进度。
- × / △ / ○ 评分、复习历史和耳词池。
- R2 音频存储和独立版本。
- 本地缓存、手动同步和 JSON 导出。

### 明确不纳入

- AI Agent 系统和训练管线。
- 文字背词、变形专项、造句检查和发音评分。
- 原生 iOS/Android 工程。
- 复杂统计、社交和成就系统。

## 13. 数据库逻辑表清单

以下为 PostgreSQL 的逻辑表分组。实际建表时使用 Flyway 迁移，并为所有业务实体使用稳定 ID。

### 13.1 账户和配置

~~~text
user_account
user_role
language_config
language_feature
system_config
audit_log
~~~

user_account 保存登录和状态；词典内容不保存用户学习状态。language_config 保存语言、脚本、发音 locale、释义语言和 TTS 配置；前端通过接口读取启用语言及功能入口。

### 13.2 词典和来源

~~~text
dictionary_source
dictionary_import_batch
dictionary_import_row
dictionary_entry
dictionary_entry_revision
dictionary_pronunciation
dictionary_sense
dictionary_gloss
example_sentence
sense_example
dictionary_form
lexical_relation
entry_component
dictionary_migration
character
~~~

dictionary_entry 的唯一身份是 language + script + normalized_written_key。系统词典和用户贡献词条使用同一内容模型，通过 origin_type、visibility 和 moderation_status 区分。读音、词义、例句、词形和关系都是子表，不参与基准词条唯一键。

### 13.3 个人学习数据

~~~text
wordbook
personal_custom_entry
user_learning_item
wordbook_learning_item
user_learning_tag
user_note
review_event
ear_word_event
~~~

user_learning_item 必须且只能引用 dictionary_entry 或 personal_custom_entry；同一用户对同一词典条目只能存在一个学习条目。wordbook_learning_item 允许一个学习条目关联多个单词本。

### 13.4 音频、同步和备份

~~~text
audio_asset
audio_version
audio_generation_job
sync_change
sync_cursor
backup_job
backup_object
~~~

audio_version 独立记录服务商、模型、声音、文本哈希、文件哈希、R2 对象键和生成状态。同步变更使用幂等事件 ID；备份表只记录任务和对象元数据，不在数据库中保存 MP3。

### 13.5 关键约束

- dictionary_entry 对非归档条目使用 language、script 和 normalized_written_key 的唯一约束。
- dictionary_pronunciation 在同一词条内按规范化读音去重，并限制最多一个主要读音。
- dictionary_sense 和 sense_example 使用 display_order；每个词条和例句的主要项由业务规则校验。
- user_learning_item 对 user_id 和 dictionary_entry_id 建唯一约束；个人未解析项使用 user_id 和 normalized_written_key 建唯一约束。
- review_event 只追加不更新；当前 FSRS 状态由最新成功事件更新。
- 用户贡献词条被引用后不得物理删除，使用弃用、封禁或迁移。
- 词典和用户个人数据的删除、迁移、审核和发布必须写入 audit_log。

## 14. 待确认配置

- Unicode、空白和假名规范化规则的版本。
