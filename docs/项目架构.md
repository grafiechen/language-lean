# 项目架构与开发入口

当前交付的是可编译骨架和账户登录纵向切片，不是可用的学习 MVP。管理员管理页面、邮件流程、完整训练界面、FSRS 调度、TTS、自动同步及离线页面缓存仍待实现，不能把接口预留理解为这些功能已交付。

## 目录与依赖方向

- frontend/src/pages：Ionic 页面与路由。
- frontend/src/features：业务功能与 Pinia 状态，当前实现后台语言读取。
- frontend/src/core：不依赖 Vue、Dexie 或 HTTP 的复习协议、评分聚合和端口。
- frontend/src/platform/web：Web 存储适配器，当前实现多账号待上传队列的 IndexedDB 分区。
- backend：Java 21 / Spring Boot 模块化单体，一个构建和部署单元。
- backend 的业务包按 languages、reviews、accounts、dictionary、learning、audio、sync 划分；未实现模块只记录边界，不生成空控制器。
- compose.yml：本地 PostgreSQL 与 API，数据库不映射宿主端口。
- docs：需求与架构依据。

模块内部按需要细分 api/application/domain/infrastructure。业务域不得依赖页面、云 SDK 或 IndexedDB；通过端口接入基础设施。不提前拆微服务或为每个领域创建 Maven 子工程。

## 数据访问约定

业务数据库操作统一使用 Spring Data JPA：Controller → Service（事务边界）→ Repository → Entity。当前语言接口已采用 JPA 实体、复合主键映射、Repository 派生查询和 EntityGraph 关联加载；Controller 不编写 SQL，实体不直接作为 API 响应。

Flyway 负责结构和初始配置迁移，Hibernate ddl-auto=validate 只验证映射，不自动修改生产表结构。后续模块沿用此约定；当前不混用 MyBatis-Plus 或直接 JDBC。

## 注释约定

- Flyway 迁移为业务表和不直观的关键字段添加 COMMENT ON，说明用途、身份、版本及删除边界。
- Java 类和关键业务方法使用 Javadoc，重点说明职责、事务、权限和幂等行为；JPA 必需的无参构造也说明用途。
- TypeScript 对领域契约、存储适配器和有状态业务方法使用 TSDoc。Vue 模板只在交互目的不明显时注释。
- 注释解释“为什么”和边界条件；简单 getter、框架注解和显而易见的赋值不逐行复述。代码行为变化时必须同步更新注释。

## 当前纵向切片

Flyway V1 初始化日语及 LISTEN_RECALL 配置 → GET /api/v1/languages 查询数据库 → 前端语言区域展示。
公开语言读取、健康检查和 CSRF 初始化；用户名/邮箱登录、当前用户、退出及登录态改密使用服务端 Session Cookie。个人接口必须认证，管理员路径要求 ADMIN 角色。Swagger/OpenAPI 依赖已预留且默认关闭。

账号、角色和登录标识使用 JPA。用户名和邮箱都写入全局唯一的 user_login_identifier，防止一个账号的用户名与另一个账号的邮箱冲突。密码使用带 `{bcrypt}` 算法标识的单向哈希，每次生成独立随机盐；算法标识和盐包含在哈希格式中，便于以后迁移算法。数据库没有明文密码、独立盐列或可逆密钥。

首次管理员由 BOOTSTRAP_ADMIN_USERNAME、BOOTSTRAP_ADMIN_EMAIL、BOOTSTRAP_ADMIN_PASSWORD 三个环境变量共同初始化，密码至少 8 位，且必须同时包含字母、数字和特殊字符；全部留空时不创建账号，缺少任一项则启动失败。初始化幂等，不覆盖已存在账号。初始账号带 mustChangePassword 标志，首页提供改密表单。普通账号创建、邮件投递、找回密码和禁用/注销尚未实现。

第一版核心扩展接口包含 account scope、progress epoch、题型结果、逐次尝试和一次完成事件。Again 重试后 Good 仍聚合为 Again，未通过不能聚合为完成。真正的 FSRS 实现和完整队尾调度器后续接入，不用假算法模拟。

IndexedDB 的 pending/drafts/states 均以 accountKey 开头组成复合键；accountKey 由服务端稳定标识与用户 UUID 构成。acknowledge 只清除指定账号指定事件，不能用当前登录名重写旧数据归属。当前只提供存储适配器，认证上传、完整事务式轮次提交和草稿恢复尚待实现。

## 本地启动

容器预览只需可用的 Docker Engine 和 Compose（Linux 容器）；本机使用 Ubuntu WSL 内的独立引擎，无需 Docker Desktop。Java、Maven、Node 和 Nginx 均在镜像内运行。

1. 根目录复制 .env.example 为 .env，填写本地数据库密码及首次管理员三项配置。
2. 根目录执行 docker compose up --build -d，构建并启动前端、数据库与 API。
3. 首次构建需要下载基础镜像及依赖；docker compose ps 可查看容器状态。
4. 浏览器访问 http://localhost:5173。前端 Nginx 将 /api 代理到内部 api:8080，保持认证同源。
5. GET http://localhost:8080/actuator/health 返回健康状态。

Docker 引擎必须先启动。数据库不公开宿主端口；独立运行 Java 时使用自行准备的 PostgreSQL，并通过 DB_URL、DB_USER、DB_PASSWORD 指定连接。不要将数据库密码写入仓库。

停止与恢复使用 docker compose stop / start；移除容器及网络使用 docker compose down，保留数据库卷。只有确定删除本地全部数据时才使用 docker compose down --volumes。

需要宿主机热更新开发时，再安装 Java 21、Maven 3.9+、Node 22.12+；前端可单独运行 npm ci 和 npm run dev，此时需先停止 web 容器释放 5173 端口。

## 检查与构建

- frontend：npm test；npm run build。
- backend：mvn test；mvn package。
- 构建依赖由 Maven BOM 和 package-lock.json 锁定。Maven 可通过 -Dmaven.repo.local 指定缓存路径。
- 部署镜像基于支持 ARM64 的 Java/PostgreSQL 镜像；当前 Compose 仅为本地入口，不包含生产 Nginx、TLS、域名或备份自动化。
- 不把个人 API 响应放入公共 Service Worker 缓存。后续离线准备模块必须按设计文档实现账号隔离及逐资源准备状态。
