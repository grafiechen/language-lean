# 前端安全审查与测试

审查日期：2026-10-07。修复在 `feature/frontend-security`，没有合并或发布生产 main，也没有修改域名、DNS、真实账号或数据库。范围为 Vue/Ionic 前端、共享请求封装、密码传输、离线缓存、静态发布配置及 npm 依赖。属于代码审查和隔离环境验证，不是完整渗透测试。

## 已确认问题及修复

| 问题 | 风险与可利用条件 | 修复 |
| --- | --- | --- |
| `source-map-js 1.2.1` 依赖公告，高危 | 解析恶意 indexed source map 可导致事件循环拒绝服务。Vue 编译器/PostCSS 引入该包；当前应用没有向用户开放源映射解析接口，未证明在线页面存在远程攻击入口。 | 锁文件更新到 `1.2.2`。 |
| `sharp 0.35.4` 依赖公告，高危 | 上游 librsvg 内存漏洞，在特定 Linux glibc 运行条件及恶意 SVG 输入下可能执行代码。由 Wrangler → Miniflare 引入；当前静态 Worker 没有配置 Images 绑定，也没有使用 sharp 处理用户图片，属于开发/构建依赖风险。 | Wrangler 更新到 `4.148.0`；其 Miniflare 仍固定旧 sharp，因此通过 npm overrides 锁定 `sharp 0.35.5`，保留 Preview 所需版本。 |
| 应用可被外站 iframe 嵌入，中等风险 | 旧版浏览器实际允许嵌入登录页面，存在诱导点击风险。影响取决于浏览器 Cookie 的 SameSite 策略、是否为同站攻击页面以及当前操作；不等于绕过服务端鉴权。 | Cloudflare 静态 `_headers` 和 Docker Nginx 均设置 `X-Frame-Options: DENY`、CSP `frame-ancestors 'none'`。 |
| Ionic 缓存页面保留密码，低风险 | 填写登录/改密密码后跳转再返回，旧版仍保留输入。本机浏览器使用者或同源脚本可读取残留；没有发现密码被写入持久存储，也没有证据说明会直接向外站泄露。 | 登录和首页在 Ionic 离开/卸载时清空密码；登录成功立即清空；首页账号切换清空。提交同时阻止重复触发。 |

最初 npm 完整审计显示 4 个 high 包项，其中 sharp、Miniflare、Wrangler 是同一公告沿依赖链传播，不是 3 个独立漏洞。依赖公告：[source-map-js](https://github.com/advisories/GHSA-68fv-2mgg-jv7q)、[sharp 维护者公告](https://github.com/lovell/sharp/security/advisories/GHSA-wq5f-xc86-pv6w)。当前修复后的完整审计和 `--omit=dev` 审计均为 0；结果仅代表该日期的公开依赖公告。

## 附加加固与审查边界

- CSP 限制脚本为同源，禁用对象插件、base 标签和跨站表单提交；新增内联脚本在隔离 Chrome 中被实际阻止。这是纵深防御，未将“缺少 CSP”表述为已经发现 XSS。Ionic 内联样式、Blob 音频和分开部署的 API 保持可用。
- 静态响应增加 `Referrer-Policy: no-referrer`，防止词条/单词本路径向外部来源链接传播。关闭当前没有使用的相机、麦克风、定位权限。
- Cloudflare 静态资源由 Assets 提供，需要 `_headers`，不能只修改 Worker 的 404 响应；遵循[官方静态响应头说明](https://developers.cloudflare.com/workers/static-assets/headers/)。Nginx 的 sw.js/index.html 自有 `add_header` 会覆盖父级继承，均重复包含安全头配置，且错误响应使用 `always`。
- 没有找到 `v-html`、`innerHTML`、`eval` 或 `new Function` 等直接处理用户输入的危险渲染点；词条/错误提示使用 Vue 文本插值。外部来源链接限制 HTTPS，并设置 noreferrer。该检查不能证明不存在所有 XSS。
- 网络请求集中在共享封装中，API 基地址只允许 HTTP(S) 源站；写请求包含 CSRF token。密码和重置令牌使用后台签发的会话/用途绑定一次性 AES-GCM 密钥，浏览器不持久存储密钥，缺少 WebCrypto 时拒绝提交。应用层加密仍依赖 HTTPS，不能防御页面自身被注入脚本。
- 缓存账号没有邮箱、密码、权限或会话 token；离线身份不具备 ADMIN/服务端权限。实际授权仍由后端安全链、资源所属账号检查和 CSRF 完成，不能只依赖菜单或路由守卫。此轮没有对所有后端接口重新进行完整权限渗透测试。
- Service Worker 仅缓存静态应用壳，排除 API、音频和写请求。恢复文件限制大小/结构/深度，拒绝原型字段和外部资源地址，恢复前重新核对账号 UUID、服务器及当前状态。
- IndexedDB 的个人词条、笔记、学习进度和离线音频保留在当前浏览器，退出账号不会删除。这符合现有多账号断网学习要求，但共享电脑上同一浏览器资料的使用者可查看这些数据；它不是本机加密保险箱。不要把一次性网络密钥用于离线数据加密，否则过期后无法恢复学习记录。

## 验证

- WSL Docker Node 22 按锁文件执行 npm ci；140 项前端单测通过，Vue/TypeScript 类型检查和 Vite 生产构建通过。构建产物没有提交到仓库。
- Wrangler `deploy --dry-run` 通过，读到 38 个静态文件，未上传发布、未申请新绑定；生产 deploy 与非 main preview 脚本保持原有行为。
- Nginx `nginx -t` 通过。隔离 Chrome 同一套脚本分别运行旧镜像和修复镜像，实际复现两页密码残留及允许 iframe；修复后两页清空密码、iframe 被拒绝、内联脚本被 CSP 拒绝。
- 浏览器假后台解密一次登录请求，确认正文无明文密码、携带 CSRF 且 AES-GCM 用途匹配。Service Worker 缓存没有 API 响应，断网后仍可启动登录页面。只使用临时假账号和随机测试密钥。
- 最终同一套 Chrome 回归分别在 Docker Nginx 和 glibc Node 22 的 Wrangler 本地 Worker 上通过，Cloudflare 解析 4 条有效 `_headers` 规则。Preview 命令仍存在；sharp 0.35.5 在 glibc 环境解码无害 SVG 正常。
- 附带修复真实发现的 Cloudflare 离线故障：Assets 将 `/index.html` 重定向到 `/`，其缓存响应携带 redirected 标记，浏览器会拒绝拿它响应离线导航。Service Worker 在返回入口时保留正文/安全头，构造无重定向标记的响应；缓存版本同时纳入 Worker 代码及 `_headers` 指纹。新增回归测试，并在真实 Chrome + 本地 Worker 中确认重定向缓存仍可离线启动。这属于可靠性问题，不计作独立安全漏洞。
- 回归脚本 `tools/verify-frontend-security.cjs` 需要独立 Chrome/Playwright；`FRONTEND_SECURITY_URL` 指向隔离构建实例，默认 localhost:5188。脚本拦截该实例 API 并模拟响应，不应指向真实生产环境。`--baseline` 用于验证旧镜像的问题。

生产 Cloudflare 响应头和线上登录没有在本次审查中发布验证；修复发布后需检查真实响应及浏览器 Service Worker 更新。旧页面仍打开时缓存版本不会强制切换，以保护正在进行的复习。
