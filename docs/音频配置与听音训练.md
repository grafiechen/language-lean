# 音频配置与听音训练

当前已接入 Google Chirp 3 HD、Cloudflare R2 服务端适配器、后台 TTS 设置和听音回忆页面。默认不调用云服务；没有凭据时显示尚未配置，不能用静音、测试音或跳过题目代替真实发音。

公共发音读错或无法播放时，词条及例句旁可提交问题，后台“发音反馈”处理。反馈记录公开文本、词典版本和遇到的音频版本；生成失败不结单，更新音频后需人工试听并填写说明。完整流程见[公共发音反馈与测试](./公共发音反馈与测试.md)。

## 配置服务端

Google 项目需启用 Cloud Text-to-Speech API，并为服务端身份授予合成权限。使用标准 Application Default Credentials（ADC），不要把服务账号文件或 R2 密钥放进前端、数据库、Git 或聊天消息。

在未纳入 Git 的 `.env` 中设置以下变量，值替换为自己的配置：

```dotenv
GOOGLE_TTS_ENABLED=true
GOOGLE_CREDENTIALS_FILE=/mnt/d/gitHome/language-lean/.secrets/google-credentials.json
R2_ACCOUNT_ID=自己的32位账户ID
R2_ACCESS_KEY_ID=自己的R2访问密钥ID
R2_SECRET_ACCESS_KEY=自己的R2访问密钥
R2_AUDIO_BUCKET=自己的私有音频桶
```

`.secrets/` 已忽略。凭据文件在 Docker 所在的 WSL 中必须可读，生产 API 使用 UID 10001；不要为读取文件而公开整个目录。这里只挂载一个只读凭据文件。R2 使用指定桶的对象读写权限，桶保持私有，浏览器通过同源 API 播放，不需要浏览器 R2 密钥。

在 WSL 的项目根目录执行：

```bash
docker compose -f compose.yml -f compose.audio.yml up --build -d
```

热更新开发对应 `docker compose -f compose.dev.yml -f compose.audio.yml up -d`。默认预览直接执行 `docker compose up -d`，不要求存在凭据文件。开发 Compose 前端端口为 5173；本机生产式预览通过 `.env` 的 `WEB_PORT=5174` 使用 5174。

管理员在“后台词典管理 → TTS 配置”中按语言选择默认声音和生成开关。提供部分 Chirp 3 HD 声音供选择；当前配置的其他声音也保留在下拉列表中。语言禁用时禁止新生成；已有可用音频仍可读取。“允许个人音频生成”已接入私有词条及个人覆盖的保存、详情、点击及重新生成；关闭后已有内容匹配的音频仍可播放。公开读音与个人例句可分别选择音频作用域，见[个人读音与例句覆盖测试](./个人读音与例句覆盖测试.md)。

参考：[Google Chirp 3 HD](https://docs.cloud.google.com/text-to-speech/docs/chirp3-hd)、[Google 合成 REST API](https://docs.cloud.google.com/text-to-speech/docs/reference/rest/v1/text/synthesize)、[Cloudflare R2 Java SDK 示例](https://developers.cloudflare.com/r2/examples/aws/aws-sdk-java/)。

## 生成、播放和修复

保存草稿、发布和导入后，在事务提交成功后异步检查音频；云服务未配置时不会自动发起生成。打开详情和点击发音也调用补生成入口。只使用显式填写的词条或例句“发音文本”，没有填写时不生成，不能用书写形式或例句正文代替。

`V10__audio_generation.sql` 保存语言设置、独立音频资产和线性版本，MP3 仅保存到 R2。公开内容和管理员草稿分开授权。每次读取文件重新检查词条状态、资源归属和草稿权限；封禁后的新读取被拒绝。

生成使用数据库行锁、180 秒任务租约和唯一资源身份；获取锁后重新检查已有版本。内容、locale、声音、服务商及模型参与生成指纹。生成和上传不持有数据库行锁，同一进程最多并行四个生成任务。服务器或工作进程中断后租约到期可重试，旧任务的迟到结果不能覆盖新任务。

新版本上传成功才切换当前版本，失败保留旧版本但不把过期内容配给新题目。服务器读取时校验文件 SHA-256；缺失或字节损坏走同一加锁补生成流程。正确文件但发音不正确无法由哈希判断，管理员应修正发音文本或点击“重新生成发音”。

私有词条删除后，全部历史音频对象通过数据库清理任务异步删除，云端失败保留重试；生成期间删除的迟到上传也进入该任务。详情见[私有词条与个人音频测试](./私有词条与个人音频测试.md)。现存词条的旧音频版本继续保留，公开音频的保留周期和一般孤立对象扫描仍待完善。云调用失败以通用错误返回，不返回密钥、访问令牌或上游响应正文。

## 实际训练

1. 从基础词典详情加入单词本。
2. 单词本页点击“开始今日听音训练”，或用“额外训练”包含未到期词。
3. 点击“准备内容和音频”。没有发音文本的词保留在单词本并明确计数；有发音但资源准备失败时阻止开始，不能暗中跳过。
4. 准备成功后开始。每组最多十词，先听音再显示答案，用 ×／△／○ 判定。× 自动插入队尾，最后一个错词也自动重试。本轮最差判定用于一次 FSRS 更新。
5. 每次判定原子缓存；退出再进入恢复原队列。每词完成立即尝试上传，离线或会话过期则保留所属账号的待上传事件。联网并登录原账号后，在单词本页点击“上传今日学习进度”补传全部积压事件。

训练只播放准备阶段缓存的固定版本。缓存缺失或播放失败时不能评分，“重新准备当前音频”会重新检查服务端资源、下载文件并保留原答题队列；若内容已变化导致发音哈希不一致则拒绝误用音频。浏览器限制自动播放时可以手动点击播放。

IndexedDB 版本 2 增加按 `[站点来源, 用户 UUID]` 分区的音频和训练内容快照，保留版本 1 的进度数据。服务端确认后清除对应词条的过程快照，批次全部确认后清除整个草稿及训练内容；可复用的音频缓存保留。重置或最后关联删除会清除当前账号对应旧代际的草稿和待上传事件，其他账号不受影响。

离线准备页已接入静态应用壳、账号选择和单词本快照，可先联网准备，再断网关闭后重新打开继续训练。流程见[离线准备与多账号缓存](./离线准备与多账号测试.md)。联网进入页面或上传前会核对多设备删除/重置，冲突记录可重试或明确丢弃；详见[多设备同步与冲突处理](./多设备同步与冲突处理.md)。离线 FSRS 到期及连续轮次已接入，见[离线 FSRS 调度与验证](./离线FSRS调度与验证.md)；缓存用量和清理流程见[离线缓存管理与测试](./离线缓存管理与测试.md)。

## 验证范围

镜像构建执行后端完整测试、前端 Vitest、TypeScript 和生产构建。音频集成测试用可替换的合成及存储适配器覆盖并发去重、上传失败保留旧版本、文件缺失/损坏重建、权限隔离、配置变化和生成时内容变化。

浏览器验收使用独立 PostgreSQL 数据库及测试 MP3，真实调用词典、配置、学习和 FSRS API，只替换云音频请求。测试 MP3 是短测试音，位于测试资源目录，不进入生产 JAR，不作为产品发音。真实 Google 音色、权限、计费和 R2 互通需要配置自己的凭据后再验收。
