# 离线 FSRS 调度与验证

已完整准备的单词本可在断网时计算下次复习时间。完成一个词的全部必做题型后，原始答题事件和本地计算结果在同一 IndexedDB 事务中保存；本次 Again 尝试仍参与最差评分，不逐次更新 FSRS。时间到期后，该词重新进入离线日队列，到期词优先于新词。额外训练仍可包含未到期词。

## 使用方式

1. 联网登录并在“离线准备”下载单词本。除了内容和音频，现在还保存服务器提供的卡片状态及算法参数。
2. 断网进入听音训练。每词完成后显示“下次复习（待同步）”，单词本页面显示“待同步预估”。计数包含本机未上传的完整复习，属于待确认数据。
3. 当前批次完成后可点击“准备下一轮训练”。未到期词不进入日队列；初始词首次 Good 后默认十分钟到期，届时可以继续离线训练。仍采用现有学习步骤，并非所有词固定十分钟。
4. 关闭页面重新打开后，未完成的批次恢复原队列；已完成但未上传的批次保留确认关联，不阻止开始下一轮。
5. 联网并登录归属账号，点击“上传今日学习进度”。后续轮次引用前一条事件 ID，按基准链先后补传，服务器确认后清理对应本地预估。

旧版本缓存没有算法参数时仍能保存答题，但不猜测新的到期时间，并明确提示需联网确认周期；可以继续额外训练。联网重新准备单词本后，新的训练批次启用完整离线调度。已经开始的旧批次保持原基准，不能中途替换。

## 状态与参数

个人学习 API 的条目视图增加 `fsrsState` 和 `scheduler`。`fsrsState` 是当前 Java Card JSON；`scheduler` 包含协议版本、算法版本、21 项权重、目标保持率、最大间隔、学习及重新学习步骤的毫秒数组，以及随机扰动开关。参数来自当前部署的实际调度器，不由浏览器硬编码猜测。

第一版浏览器适配 `FSRS-6/java-fsrs-1.0.0`，保持 Java 的状态机、完整 24 小时取整、正数间隔四舍五入及学习步骤。当前服务器关闭随机扰动；未知版本或不支持的配置不生成预估。代码依据[官方 java-fsrs 1.0.0](https://github.com/open-spaced-repetition/java-fsrs/tree/v1.0.0)，MIT 许可随前端保存至 `public/third-party/java-fsrs-LICENSE.txt`。

训练开始时固定学习代际、基准事件、卡片及参数。连续离线轮次使用前一事件的本地结果；上传的 JSON 始终是原答题记录，客户端不把卡片预估提交为权威进度。服务器独立计算正式结果，确认后以服务器状态为准。如果离线期间部署参数改变、另一设备完成了更晚的答题或服务器已收到了尚未确认的事件，预估时间与次数可能调整。

IndexedDB v5 增加按 `[accountKey, eventId]` 保存的 `projections`，不覆盖 `states` 中的确认状态，保留 v1–v4 的事件、音频和冲突记录。投影落盘失败时整次判定回滚，队列不推进；缺少兼容参数时只保存原始答题。确认上传、重置、最后关联删除或明确丢弃依赖链时，连同对应投影一起清理，其他账号不受影响。服务端没有新增 SQL 迁移，仍使用 V1–V10。

## 验证

后端 46 项、前端 61 项测试及 TypeScript/生产构建通过。固定的 108 组 Java 结果在两端分别验证，并额外核对连续多轮本地结果作为下一轮基准时的到期时间；覆盖初始各评分、当天及跨日复习、重新学习、不同保持率和最大间隔。到期时间、状态、步骤及卡片整数 ID 一致，稳定度和难度允许浮点数的微小舍入差异。

基准文件分别位于 `backend/src/test/resources/fsrs-parity.json` 和 `frontend/src/core/fsrs.fixtures.json`，内容及 SHA-256 相同。普通测试只读取固定结果；算法升级时才显式生成并审查：在后端执行 `mvn -Dtest=FsrsParityTest -Dfsrs.fixture.output=src/test/resources/fsrs-parity.json test`，核对后复制到前端对应位置，再运行两端完整测试。不能通过自动重生成预期值掩盖算法差异。

真实浏览器在独立 PostgreSQL 中验证：首次离线完成后未到期排除，关闭页面后按模拟时间到期重新进入，连续第二轮引用原事件补传，正式时间与本地预估一致，确认后事件和投影清理。另已回归双设备重置、删除后重加、冲突持久化和依赖链丢弃。390px 无横向溢出，未发现运行时错误。测试只替换云音频，真实 Google/R2 发音互通仍需用户配置后验收。
