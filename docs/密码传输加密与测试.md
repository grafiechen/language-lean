# 密码传输加密

更新日期：2026-10-06。

本次范围为登录、登录态改密、邮件链接重置密码、账号注销及管理员删除账号。重置链接的凭证与密码一起加密。当前没有验证码接口；新增时必须加入同一套接口清单。账号邮箱、公开词典和普通学习请求不做应用层加密。个人学习备份导出暂时关闭：页面没有导出按钮，`GET /api/v1/learning/export` 不再提供；恢复已有备份仍可用。

## 请求协议

1. 浏览器获取 `/api/v1/auth/csrf`。
2. 使用 CSRF 请求头向 `POST /api/v1/auth/password-key` 提交 `{ "path": "/api/v1/auth/login" }`。后台生成随机32字节密钥，返回 `keyId`、`algorithm: AES-256-GCM`、Base64 编码的 `key` 和服务器 `expiresAt`；响应 `Cache-Control: no-store`。
3. 前端用 Web Crypto 将完整原始 JSON 请求体加密。使用随机12字节 IV、128位认证标签，附加认证数据为 UTF-8 的 `password-v1|<keyId>|<接口路径>`。
4. 向原接口提交 JSON `{ "keyId": "UUID", "nonce": "Base64", "ciphertext": "Base64" }`。`ciphertext` 包含密文和 GCM 标签。登录也使用此 JSON 外壳，不再传输明文表单。
5. 后端先验证 CSRF，再用会话及具体接口路径验证密钥归属。通过 JPA 行锁在独立事务中删除密钥，提交删除之后解密。密码错误、认证标签错误、过期或后续业务失败不能恢复已消费的密钥。

密钥有效期为服务器签发后120秒；客户端时钟不参与是否过期的判断。密钥绑定 Session ID 摘要及精确接口路径，其他会话无法消费，登录轮换 Session ID 后旧钥无法使用。每个会话最多8个未过期密钥，每个连接来源每分钟最多120次申请，限流内存最多4096个来源。过期数据库行每分钟清理；第一版限流和 Session 适用于单应用实例。代理部署中连接来源可能是反向代理，不能直接信任客户端填写的转发地址。

前端只在当前提交中持有密钥，不写入 IndexedDB、localStorage、URL 或日志；提交结束清除可擦除的字节数组和取钥对象中的字符串引用。JavaScript 字符串和导入的 CryptoKey 由浏览器回收，无法保证物理内存立即擦除。缺少 Web Crypto 的非安全浏览器直接提示使用 HTTPS/localhost，不降级为明文。失败后用户重新提交会取新钥，不自动重放改密或注销操作。

## 数据库与服务器主密钥

Flyway V20 新增 `password_transport_key`。数据库只保存密钥标识、会话摘要、用途、截止时间及主密钥加密的密钥，不存密码、原始 Session Cookie 或明文临时密钥。临时密钥使用 AES-256-GCM 包装，格式为 `Base64(12字节IV + 密文 + 标签)`；包装的认证数据包含行标识、会话摘要和用途，复制到其他行也无法正确解密。

`PASSWORD_TRANSPORT_MASTER_KEY` 是 Base64 编码的随机32字节服务器主密钥，仅放在服务器环境变量或其私有配置中，不能设为前端 VITE 变量、存进数据库或提交仓库。Compose 已预留此项。启用 `SESSION_COOKIE_SECURE=true` 的 HTTPS 部署缺少此项会拒绝启动；本地开发留空会生成进程级随机主密钥，应用重启后旧临时密钥失效，重新取钥即可。切换主密钥同样会使在途请求失败；这些密钥没有历史恢复用途，旧行会自动过期删除。

账号密码仍使用 BCrypt 单向哈希，随机盐包含在哈希中，无需另设可逆密码密钥。邮件重置凭证仍仅存 SHA-256 摘要；它们不需要可逆加密。SMTP、R2 等现有凭据来自服务器配置，没有数据库中的明文密钥字段。

## 安全边界和上线顺序

HTTPS 仍然必需：同时拿到签发的密钥和请求密文即可离线解密；应用层加密不能替代 TLS，也不能防止已执行脚本的浏览器被控制。后台可以拒绝过期或重放的请求，不能撤销客户端已经获取的解密能力。不把密文和解密密钥一起放进业务响应。

本次接口变更拒绝明文兼容回退。上线时先准备服务器主密钥并升级后端、验证取钥接口，再发布前端；Cloudflare 自动构建不代表 OCI 后端已同步升级。旧前端需重新加载最新版才能登录。真实密钥由部署环境生成，示例文件不含真实值。

## 验证

2026-10-06 验证通过：后端完整127项测试、前端完整134项测试及两端正式Docker镜像构建；独立临时PostgreSQL17执行Flyway V20成功。隔离Chrome实际页面登录和改密成功，网络请求只含加密外壳，重放返回400，个人导出接口返回404，取钥响应为no-store。临时环境不使用现有用户数据库，也未部署OCI或发布Cloudflare生产环境。

- 前端使用真正的 Web Crypto 验证加解密、UTF-8 密码、用途绑定、篡改拒绝、逐次取新钥、不发送明文和不安全环境拒绝。
- 后端 HTTP 集成验证登录及账号操作、旧明文请求拒绝、取钥 CSRF、会话隔离、服务器过期、错误密码消耗密钥、并发只消费一次、畸形请求及数量上限。
- 数据库验证保存的是包装密文；单元验证主密钥长度、生产配置约束、随机IV、包装认证绑定及不同主密钥不可解密。
- 已登录管理员访问旧个人导出接口返回404。内部导出快照服务仍供恢复校验及测试使用，不能通过 HTTP 调用导出。

实现使用标准 JCA / Web Crypto AES-GCM，密码存储和密钥存储分别处理。依据：[OWASP Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)、[OWASP Key Management](https://cheatsheetseries.owasp.org/cheatsheets/Key_Management_Cheat_Sheet.html)。
